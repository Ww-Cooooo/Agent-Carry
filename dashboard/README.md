# Agent Carry 离线看板

看板是 Agent Carry 的本地只读界面。最终用户双击仓库根目录的 `dashboard.html` 即可离线打开，不需要终端、本地服务、Node 或网络。

## 用户看到的五个入口

- **总览**：自然语言开场、助手核心、第一次设置或当前待办。
- **随身资产**：记忆、固定流程（SOP）、能力和真实任务经验。记忆页面先说明“默认由任务自动命中、只按需读取正文”，手动按钮只是指定某一条时的补充；记忆卡片和详情使用与流程／能力不同的样式，避免让用户误以为三者共用同一内容。流程／能力页面先显示一条四步小路线，点击后再展开“候选从哪里来、怎样验证、何时复核”的完整说明；经验页面也先给简要路线，再在弹窗中解释四类资产的区别以及何时复制经验参考指令。
- **待办与成长**：普通待办、学习建议和长期改进，三者分开表达，并用真实规则图解释它们如何进入、成熟或被提醒。
- **迁移与安全**：首先区分“同一台电脑换本地 Agent”和“把整个 Agent Carry 带到另一台电脑”；后者会准备一个固定五文件迁移套件，其中有助手主体包、单独的本地隐私包、固定入口 `START-RESTORE.md`、顶层清单和校验文件。两个包各有逐文件内部清单，GitHub 私密备份、隐私包导出与导入仍作为独立操作展示。
- **当前状态**：模型、快照、渐进上下文、实例身份和维护者信息。

首页行星与卫星是导航，不是数据真源。点击卫星只进入对应栏目，不会提前加载资产正文。

## 数据与动作

运行时读取 `dashboard/dist/snapshot.js` 中的 `window.AGENT_CARRY_SNAPSHOT`。快照是可删除、可重建的本地派生物：Agent 在实例化、正式资产变化、模型确认、升级或用户明确要求重建时，按 `core/schemas/dashboard-snapshot.schema.md` 重新生成并原子替换它。Schema 1.1 为每条学习建议增加低敏来源说明、建议资产类型和下一步；这些字段帮助用户理解候选，不包含原始事件 ID、路径、日志或隐私。

看板每 60 秒只在后台重新读取这个小文件，页面上的手动按钮也只是立即“重新读取本地快照”。两者都会附加缓存规避参数；数据没有变化时不重绘，发生变化时保留当前栏目、滚动位置和 Three.js 场景。它不扫描正式记忆、不运行常驻服务、不修改资产，也不执行 Git。若重新读取后仍显示可能过期，应复制 `dashboard.refresh-snapshot` 完整请求，让 Agent 核对来源摘要并真正重建。

右上角的本地看板状态是可点击入口，并与“当前状态”页共用一套判断。正常时会说明它只代表本机看板已读取最近生成的数据，不代表 GitHub 或云端同步；更新时间缺失、格式异常、超过有效范围、晚于本机时间、状态文件不可用或重新读取失败时，会改用警示状态。弹窗直接说明原因和处理顺序，并按情况提供“重新读取本地数据”“复制修复指令”或“回到总览开始设置”，不要求用户猜绿色或黄色圆点的含义。

需要执行的按钮只复制完整自然语言请求。请求通过稳定动作 ID 和正式地图交给当前 Agent；看板自身不会创建仓库、打包、导入、推送或发布。`host.prepare-agent-switch` 只处理同一台电脑上的本地 Agent 接入：能读文件时共用同一份资产主本，只能传文字时生成当前任务所需的极小胶囊。`instance.prepare-complete-migration` 才处理另一台电脑的整套迁移，并保持两个包彼此独立；当前 Agent 按 `core/schemas/migration-kit.schema.md` 和正式模板生成套件，完成后逐字交付“请先读取迁移套件里的 START-RESTORE.md，按照里面的步骤帮我恢复 Agent Carry，完成后告诉我检查结果。”动作不从展示快照读取：快照即使出现 `actions` 字段也会被忽略，修改正式动作后必须同步离线镜像并重新构建看板。

模板首页的 `instance.instantiate` 使用三步只读向导：先选“一步步引导／适度引导／直接协作”，再选“通用／专业／先帮我判断”，最后核对并生成完整请求。交流方式与助手方向相互独立，不形成六套固定用户等级；“先帮我判断”也不是第三种正式方向。选择只保存在当前页面内，不直接写文件。正式实例的“当前状态”会显示交流方式，并通过 `profile.adjust-guidance-mode` 只修改该极小偏好和派生快照，不改变方向或既有资产。

模板快照必须是真实空态，不能含示例身份、演示资产或维护者治理日期。用于长内容、缺失字段和在线演示的合成数据只保存在私密维护夹具中，不属于公开 `main`、正式压缩包或用户安装目录。

## 开发

只有修改前端的开发者需要 Node：

```text
cd dashboard
npm install
npm run dev
npm run build
npm run analyze
```

`npm run build` 会把应用脚本和样式内联进 `dist/index.html`，确保 `file://` 下可用。Noto Sans SC、Space Grotesk、Noto Sans Mono CJK SC、快照和许可证包作为本地同目录资源分发；不访问 CDN，也不依赖用户预装中文字体。不要删除 `scripts/make-offline.mjs`，否则浏览器可能因本地 ES 模块限制显示空白。

构建开始时会自动核对正式动作登记表、安装后首次创建契约、第三方许可证清单和开源合规清单；首次创建检查确保安装入口、ZIP 交接、极小启动、实例化指南、README 与看板仍共同要求“创建助手优先、看板和聊天双入口、三种路线有解释、生成指令交回当前聊天、Level 1 迎接与 Level 3 正式实例化分离”，并拒绝退化成只报安装完成或提前写入模板。构建结束后再检查字体哈希、OFL 文本、生产依赖声明、shadcn/ui 改写源码声明、根入口与远端资源。`npm run analyze` 只在 `.assistant-local/dashboard/` 生成维护者本地包体报告，不会把分析面板塞进看板或最终安装包。这些工具只服务于前端维护，不会出现在最终用户双击看板的流程中。

字体职责与固定来源见 `public/fonts/font-manifest.json`，改写源码映射见 `public/licenses/source-code/source-components.json`，完整第三方说明见仓库根目录 `THIRD_PARTY_NOTICES.md`。变更 npm 运行依赖后先执行 `npm run licenses:generate` 并审核结果；日常构建只校验，不会静默改写声明文件。新增源码模板或二进制素材时运行 `npm run check:compliance`，未登记内容会关闭门禁。

如果 Agent 已在 `.assistant-local/dashboard/snapshot.js` 生成快照，可以运行：

```text
node dashboard/scripts/sync-snapshot.mjs
```

这个助手只复制已经生成的快照，不扫描正式资产，也不把快照写回真源。

## 正式安装与在线演示

公开仓库的 `main` 和正式压缩包只带空模板。项目主页可以链接到同一套界面的 GitHub Pages 演示，但 Pages 使用单独的纯虚构快照，并在页面顶部持续说明“这是在线演示，正式安装从空模板开始”。演示数据源、构建辅助和发布记录属于私密维护层；公开 `gh-pages` 只接收已经编译、检查过的静态站点。

看板界面变化时，维护者必须先重建正式离线产物，再用同一份 `dist/index.html` 生成 Pages 候选，并核对两者界面摘要相同。正式快照继续验证空态，演示快照继续验证纯虚构标记；不能为了在线展示维护第二套组件，也不能让演示数据回流到安装包。

私密维护夹具另外覆盖真实长度、多类别、完成／隐藏待办、长期改进和字段缺失等情形。它们只用于本地验收与 Pages 投影。正式构建结束时必须恢复 `public/snapshot.js` 的模板空态。
