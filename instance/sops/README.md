# 任务 SOP（实例拥有）

- 格式：Markdown + 前置元数据。
- 模板：`core/templates/sop/blank-sop.md`。

## 怎样找到一份 SOP

正式小型索引只有 `instance/maps/domain-map.toml` 一份；命中路线后才读取对应正文。本说明不再维护第二张手工表，避免地图、正文和看板出现三份不同状态。

用户可以只描述想得到的结果，不需要准确说出 SOP 名称。路线中的 `triggers`、`aliases`、对象、范围和排除条件必须允许日常说法先缩小到少量候选；只有选中后才读取 SOP 正文。

## 规则

- SOP 是完整的可携带核心，清楚描述目的／非目标、触发／排除、所需资产、输入、四方职责、步骤、分支、能力需求、风险、验证、失败恢复、用户输出和学习更新。
- 网页/软件/硬件变化时先基于语义目标定位，再观察、确认、执行；失败后先修正当前任务并形成任务内偏差预览，只有用户选择“先观察／留下”或已有合法候选已命中时才持久记录。
- 宿主专属的命令、按钮、路径和工具映射另写为宿主执行经验，不能取代核心语义。
- SOP 是否允许使用看授权，是否可靠看真实证据成熟度；普通低风险 SOP 在日常任务中渐进验证，不要求企业级回归。
- 真实任务中出现一套可能复用的步骤时，Agent 主动使用用户当前交流语言说明“以后哪类任务能沿用、这次是否已经验证”，再询问用户是否留下；不能要求用户先判断它是否应该叫 SOP。
