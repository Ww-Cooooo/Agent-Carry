# 看板设计与前端架构

## 1. 看板负责什么

Agent Carry 看板是本地、离线、只读的产品界面。它帮助不熟悉代码的用户回答五个问题：

1. 现在有哪些待办，应该从哪里开始；
2. 哪些记忆、流程、能力和经验能跟着自己迁移；
3. 助手正在怎样学习，是否有待办或长期改进计划；
4. 换 Agent、换模型或换电脑时该走哪条迁移通道；
5. 当前模型是否合适、Level 1／2／3 分别什么时候用，以及看板数据和按需读取是否正常。

看板不是真源，不直接改记忆、SOP、能力、治理卡或 Git。需要执行的按钮只复制一份完整自然语言请求，由用户交给当前 Agent；Agent 再通过稳定 `action_id`、地图和协议定位正式流程。这让看板保持跨系统、跨宿主和离线可用，也避免把文件写入能力隐藏在网页事件里。

## 2. 设计方向：Portable Orbit

首页中央的行星代表 Agent Carry，外部镂空蓝色框架代表可以持续增加内容的助手核心，周围卫星分别通向记忆、固定流程（SOP）、能力、待办、经验、长期改进、学习建议和当前模型。用户不用理解文件结构，也能从这些入口找到已经保存的内容。

这个视觉只承担品牌识别和导航，不承担统计图表。页面其他区域保持浅色、安静、清楚，让视觉重点只有一个：

- 背景使用低对比云白与冷灰蓝，不使用大面积深色；
- 主色只使用 Carry Blue，卫星颜色只用于分类和少量状态提示；
- 阴影短而轻，避免脏雾、过度玻璃感和廉价发光；
- 三维核心有缓慢呼吸、转动和指针视差，卫星有克制的轨道运动；
- 用户要求减少动画时，关闭非必要移动与页面过渡；
- 不把所有卡片做成同一种“模板化大圆角”，通过切角、边界和留白建立层级。

## 3. 信息架构

旧结构按内部资产类型逐层展开，用户首先看到的是系统分类和统计图。新版按用户意图组织为五个入口：

| 入口 | 用户问题 | 主要内容 |
| --- | --- | --- |
| 总览 | 我现在应该做什么 | 自然语言开场、助手核心、第一次设置或下一待办、资产概览、最近变化 |
| 随身资产 | 有什么会跟着我走 | 记忆、固定流程（SOP）、能力、经验；支持分类、搜索、详情和复制调用请求；页面先用紧凑小流程概括形成或使用路线，点击后再打开完整验证／复核或经验说明 |
| 待办与成长 | 还有什么要做，助手如何变好 | 普通待办、学习建议、长期改进；三者不混为一种任务 |
| 迁移与安全 | 怎样换 Agent、换电脑或做远程私密备份 | 独立区分同机换本地 Agent 与整套换机迁移；整套迁移包含助手主体包、单独隐私包和恢复校验说明；另有 GitHub 私密备份、隐私包导出／导入和安全提醒 |
| 当前状态 | 现在是否正常、该用哪个等级 | 看板数据、当前模型、Level 1／2／3 用途、随身内容、按需读取、实例身份与维护者信息 |

首页有八个卫星入口：七个内容组（记忆、固定流程、能力、待办、经验、长期改进、学习建议）加一个当前模型状态。当前模型只是运行状态，不属于可携带资产。卫星和分类坞只做深链接，不预读正文，也不把这些内容一次塞进模型上下文。

模板首页仍只保留一个“创建我的助手”首要操作。点击后使用三步弹窗承载必要选择，而不是在首页铺开六张组合卡：第一步选择可调整的交流方式，第二步选择通用／专业方向或“先帮我判断”，第三步核对并生成完整 Agent 请求。弹窗选择只存在于当前页面内，关闭或刷新可以丢弃；它不直接写清单。正式实例的“当前状态”显示当前交流方式，并可生成只调整 `profile.guidance_mode` 的请求；方向没有修改入口。

## 4. 文案原则

看板默认面对不懂编程的用户，因此先说“用户要完成什么”，再说内部术语：

- 使用“创建我的助手”“带到另一台电脑”“看看随身资产”等动作与对象完整的标签；
- “一步步引导／适度引导／直接协作”只描述交流方式，不写成用户等级；三者都能创建通用或专业助手，避免默认用户是小白或程序员；
- 第一次出现 SOP 时写作“固定流程（SOP）”；
- 不把内部机制名、数据结构名或路由术语直接交给普通用户；需要保留的 Level、SOP、GitHub 等名称必须紧邻解释；
- 固定流程和能力在普通界面只显示“待验证、需要复核、可使用”。详细成熟度与验证证据继续保存在正式资产中；
- 状态旁的问号只补充一句简短含义。用户该去哪里验证或复核，必须在页面中直接说明，不能藏进悬停提示；
- 每条学习建议在列表和详情中都要让用户看见“从哪里发现、为什么可能值得留下、当前建议保存成什么、处于什么状态、下一步怎样处理”。来源只显示低敏自然语言摘要，不展示事件 ID、路径、日志、隐私或外部攻击载荷；建议去向不等于已经生成正式资产；
- 形成、验证和经验说明不能长期占据整页。页面先显示能一眼读完的四步小流程；用户点击后，使用有焦点管理的弹窗展开完整规则。紧凑展示只减少视觉负担，不能删掉来源、证据、边界或失败处理；
- 固定流程和能力页面必须把正式成熟路线翻译成可视顺序：首次使用前为待验证；第 1 次独立成功后可使用；第 2 次继续积累但不机械升级；通常至少 3 次独立成功、2 种任务情境、范围稳定且无未解决重要失败后才记为可靠；达到可靠后再经过真实跨宿主或实质环境变化验证。任务内重试只算一次，高风险资产可以要求更多证据；
- 首次使用之前必须先解释资产来源：真实任务或用户要求产生学习信号，Agent 先形成有来源、有范围的候选，再判断它属于能力、固定流程还是经验；获得保存授权不等于已经验证，没有成功证据时仍为“待验证”；
- 失败、环境／版本／权限变化或证据冲突会让任何阶段进入“需要复核”。页面要直接画出检查旧证据与当前环境、在下一项合适真实任务中重新验证、按结果恢复或继续复核的路线；
- 经验页面要清楚解释它是一次真实任务的复盘记录，包含背景、成败、修正、证据和边界；它不同于长期事实／偏好的记忆、说明会做什么的能力和规定复用步骤的固定流程，也不会在新任务中被原样照搬。详细弹窗还要说明：只在当前任务与某条经验真正相似时打开卡片、复制参考指令、交给当前 Agent 按需读取，并先比较当前条件再采用；
- 模板空态解释下一步，不展示维护者的示例身份、具体日期或演示资产；
- 没有待办、学习建议或长期改进项时保持安静，不为了显得活跃而制造数据；
- 技术字段收进“给维护者看的技术信息”，不占据日常首屏；
- 复制请求必须包含目标、稳定 ID、路由、范围、禁止事项、确认点和完成回报，不能只复制一句含糊口令。

## 5. 数据与动作边界

```text
正式 Markdown / TOML 资产
          ↓ 由 Agent 按 Schema 生成
本地 snapshot.js（可删除、可重建的只读投影）
          ↓ 前端读取并展示
看板卡片与状态
          ↓ 用户点击
完整自然语言请求 → 当前 Agent → 地图 / 协议 → 正式操作
```

数据契约由 `core/schemas/dashboard-snapshot.schema.md` 拥有。全局动作的正式登记表是 `core/maps/dashboard-actions.toml`，字段与执行边界分别由 `core/schemas/dashboard-action.schema.md` 和 `core/protocols/DASHBOARD_ACTIONS.md` 约束。`dashboard/src/lib/data.ts` 保存供离线产物使用的编译镜像，必须通过验收与正式登记表保持一致；动作新增或修改后要重新构建看板。快照只携带展示数据，任何 `actions` 字段都会被前端忽略，不能覆盖或凭空创建按钮请求。前端不得：

- 直接扫描整个资产库；
- 把快照反向写回正式资产；
- 用演示文案替代快照中缺失的真实说明；
- 把页面自己的 60 秒读取倒计时当作长期治理调度器；
- 在 GitHub 私密备份的本地检查和仓库预览完成前创建仓库、提交或推送，或自动改为公开仓库、添加协作者；
- 把 API 密钥、密码、令牌、Cookie、私钥、恢复码或登录态放进快照、复制请求或模型上下文。

创建助手向导必须维持只读边界：网页可以把用户刚刚选择的交流方式和方向意向附加到受控 `instance.instantiate` 请求，但不能写 `instance/manifest.toml`。“先帮我判断”只能让 Agent 了解情况和提供比较，在用户明确选择 `general` 或 `domain` 前不得锁定。调整交流方式使用独立的 `profile.adjust-guidance-mode` 动作，只允许更新 `profile.guidance_mode` 和重建快照；不得重做实例化、改变 `direction` 或改写长期资产。

右上角状态不能只是颜色提示，也不能与“当前状态”页各自判断。两处必须共用同一状态函数，至少区分：正常本地同步、模板未设置、快照不可用、更新时间缺失／异常、数据超过有效范围、本机时间不一致和重新读取失败。状态入口使用可聚焦按钮打开有焦点管理的说明弹窗，直接回答“这是什么意思、为什么出现、现在怎么处理”；正常状态明确它不是 GitHub／云同步，异常状态优先提供本地重新读取，持续异常时再复制 `dashboard.refresh-snapshot` 修复请求。颜色只作辅助，文字、图标和操作必须独立表达含义。

迁移页必须先让用户选择去向，不能再用一个含糊按钮同时代表换 Agent 和换电脑：

- `host.prepare-agent-switch` 只用于同一台电脑上的另一个本地 Agent。能读取当前目录时，新 Agent 接入同一份可携带主本；只能交换文字时生成当前接入和任务所需的有界胶囊。它不得打包或重复复制整套资产；
- `instance.prepare-complete-migration` 用于另一台电脑。它按 `core/schemas/migration-kit.schema.md` 生成一个固定五文件迁移套件：`agent-carry-body-<kit-id>.zip` 助手主体包、`agent-carry-private-<kit-id>.zip` 本地隐私包、固定 `START-RESTORE.md` 入口、`MIGRATION-MANIFEST.toml` 和 `CHECKSUMS.sha256`。两个包永远分开并各有逐文件内部清单；固定入口引导新 Agent 恢复已经沉淀进 Agent Carry 的身份、记忆、能力、SOP、经验、成长、待办和长期状态。秘密凭据与宿主原生隐藏状态不进入包；GitHub 私密备份只是可选通道，不是换机前提；
- 两个入口都只复制完整请求。看板不会自行打包、外发、上传、删除源实例或宣称宿主中尚未导入 Agent Carry 的记忆已经迁移。

记忆页要同时消除两个误解：用户不需要先点卡片才能让记忆生效，也不应以为全部记忆会在启动时进入上下文。页面固定解释“说出任务 → 极小目录判断相关性 → 只读取命中的少量记忆”；卡片上的手动操作必须标为可选补充。记忆列表和详情在形状、信息结构和动作配色上与流程／能力区分，但仍复用同一设计系统。

正式状态变化时，执行该变化的 Agent 必须一并重建快照：先生成临时文件，校验后原子替换 `snapshot.js`。页面每 60 秒或用户点击“重新读取本地快照”时，只用带时间戳的查询参数重新读取这个小文件；没有变化就不重绘，发生变化时保留当前栏目、滚动位置与 Three.js 实例。页面没有扫描正式资产的权限，因此只能依据 `generated_at` 与 `freshness_seconds` 给出保守的过期提示，不能自行证明来源文件已经变化。需要核对来源摘要或真正重建时，用户复制 `dashboard.refresh-snapshot` 请求交给 Agent。

### 5.1 在线演示不是安装内容

项目 README 可以链接到公开仓库的 GitHub Pages 演示。它不是第二套看板：页面必须直接复用当前正式构建的 `dist/index.html`、本地字体、许可证和交互代码，只把 `snapshot.js` 替换成经过检查的纯虚构快照。页面顶部必须持续显示“在线演示、纯虚构数据、正式安装从空模板开始”，不能让访问者把示例身份、日期、待办或资产当成自己的内容。

公开 `main`、源码压缩包、Release 安装包和本地安装目录不得包含演示快照或私密维护夹具。演示数据源与构建辅助只存在于不公开的维护层；公开 `gh-pages` 分支只保存可直接托管的静态演示产物。看板每次变化都要同时验证两个投影：正式产物仍是模板空态，Pages 候选的界面文件摘要与正式构建一致且只有快照和 Pages 标记不同。README 中的在线链接只有在远程 Pages 页面回读成功后才算可用。

在线演示的按钮仍只是页面交互与复制请求，不会修改访问者设备。Pages 不收集用户资料、不处理秘密、不承担登录、交易或 SaaS 后端功能。公开仓库与 Pages 的实际写入属于维护者发布动作，必须在私密 Level 3 发布流程中单独预览和授权；普通用户和公开模板不需要读取这套流程。

## 6. 前端组成

| 层 | 选择 | 作用 |
| --- | --- | --- |
| 应用 | React 19 + TypeScript | 状态、路由、视图组合和可维护组件边界 |
| 构建 | Vite 8 | 开发体验与生产打包；最终通过适配脚本生成可由 `file://` 打开的离线页面 |
| 三维 | Three.js | 首页行星、镂空框架、卫星、轨道、光照与指针视差 |
| 动效 | Motion | 页面切换、进入视口动画、首页首要操作的轻微呼吸反馈与系统减少动画偏好 |
| 关系图 | React Flow | 用真实协议解释待办、学习建议与长期改进的流转；不提供无意义拖拽、缩放或控制面板 |
| 长页滚动 | Lenis | 只增强桌面主内容的滚轮连续性；触屏、减少动态、页面隐藏或不适用环境自动退回原生滚动 |
| 交互基础 | Radix UI | 对话框等需要键盘、焦点和 ARIA 语义的基础组件 |
| 组件模板 | shadcn/ui（改写源码） | 按钮、徽章、对话框和 Tailwind v4 主题脚手架；保留 MIT 来源映射与修改说明 |
| 样式 | Tailwind CSS 构建能力 + 项目设计令牌 | 生成基础能力；主要视觉由项目自己的语义类和设计令牌控制 |
| 图标 | Lucide | 一致、可访问的开源线性图标 |

这些直接运行依赖采用允许开源分发的许可证；准确版本以 `dashboard/package.json` 和锁文件为准。React、Three.js、Motion、React Flow、Lenis、Radix UI 与 Tailwind CSS 使用 MIT 许可，Lucide React 使用 ISC，`class-variance-authority` 使用 Apache-2.0。React Flow 的生产依赖中包含 BSD-3-Clause 的 `d3-ease`，完整文本随生产依赖清单分发。shadcn/ui 模板不是 npm 依赖，而是已修改并保存在仓库中的 MIT 源码，因此由单独的来源清单覆盖。看板把应用代码和框架编译进离线 `index.html`，不在用户打开时读取 npm、CDN 或远端脚本。

字体采用三个清楚分工且全部可随包分发的 OFL 1.1 家族：Noto Sans SC 负责中文正文、常规英文与数字；Space Grotesk 负责品牌标题和展示数字；Noto Sans Mono CJK SC 的 Regular／Bold 负责代码、路径、ID 与中英技术文本。完整字符集转成 WOFF2 后随仓库分发，不依赖微软雅黑、苹方等平台字体，也不做可能让姓名或专业术语缺字的常用汉字裁剪。

字号不是由各组件随意决定，而是由 `index.css` 中的语义层级统一控制：12px 只供版本号、数量、时间和状态等短元数据使用；13px 用于辅助说明；14px 用于标签与卡片正文；15px 用于主要控件；16px 是常规正文基线；17px 用于需要更强阅读连续性的正文；26px 是常规分区标题。首页与页面主标题在 32–46px 之间随可用宽度平滑变化。正文采用约 1.6–1.72 的行高，标题采用更紧凑的行高。放大字号时允许同步增加导航宽度、控件高度与窄窗口图例行数，不能用截断、重叠或缩回小字来维持旧布局。

Agent Carry 自身采用根目录 `LICENSE` 中的 Apache License 2.0；根目录的 `THIRD_PARTY_NOTICES.md` 单独说明依赖、改写源码与字体。`dashboard/public/licenses/` 保存字体原始 OFL、shadcn/ui 来源映射与 MIT 文本，以及当前锁文件中全部非 dev 依赖的机器清单和许可证全文，并在构建时原样复制到 `dashboard/dist/licenses/`。`font-manifest.json` 固定字体版本、版权、Reserved Font Name 审核、上游提交、源文件与产物 SHA-256 及转换验证。构建会拒绝过期许可证清单、未审核依赖许可、未登记二进制素材、缺失字体、校验和不符或远端运行资源。完整规则见 [开源合规与第三方来源](open-source-compliance.md)。

主要代码边界：

- `dashboard/src/Dashboard.tsx`：应用外壳、导航、快照热更新、路由和全局对话框；
- `dashboard/src/dashboard-config.tsx`：稳定分类、卫星、导航和 Hash 路由映射；
- `dashboard/src/components/dashboard/Views.tsx`：五个面向用户的视图；
- `dashboard/src/components/dashboard/AssetGuides.tsx`：固定流程／能力与经验的紧凑四步入口，以及点击后出现的来源、验证、复核、资产对比和经验使用详情弹窗；
- `dashboard/src/components/dashboard/GrowthGuide.tsx`：待办、学习建议和长期改进的只读关系图，以及电脑窗口过窄时的等价文字流程；
- `dashboard/src/components/dashboard/Shared.tsx`：共享状态、空态、详情和复制对话框；
- `dashboard/src/components/three/Core.tsx`：独立的 Three.js 场景与生命周期；
- `dashboard/src/lib/data.ts`：快照投影、完整自然语言请求生成，以及正式动作登记的离线编译镜像；它不是动作真源，也不接受快照覆盖动作；
- `dashboard/src/index.css`：设计令牌、电脑窗口布局、状态和减少动画规则；
- `dashboard/scripts/make-offline.mjs`：把生产脚本与样式内联，保留可替换的外部快照与本地字体。
- `dashboard/scripts/validate-action-mirror.mjs`：构建前核对正式动作登记与离线镜像，并保证快照动作覆盖保持关闭。
- `dashboard/scripts/generate-third-party-notices.mjs`：从锁文件和已安装包元数据生成／核对随离线产物分发的生产依赖许可证包；上游 npm 包漏装许可证时只允许使用有固定官方来源的补充文件。
- `dashboard/scripts/validate-offline-assets.mjs`：构建后核对字体哈希、OFL、生产依赖声明、根入口及所有运行资源均为本地文件。
- `rollup-plugin-visualizer`：只在维护者运行 `npm run analyze` 时把本地包体报告写入 `.assistant-local/dashboard/`，不进入页面或分发包。
- `dashboard/public/fonts/font-manifest.json`：字体职责、版本、上游来源、完整字符策略与 SHA-256 真源。

## 7. 为什么只加入有明确职责的框架

技术选择以产品适配为准，不以依赖数量为目标：

- 没有迁移到 Astro。Astro 的内容驱动、服务端优先模型很适合文档站和内容站；当前看板是一个本地、状态化、以交互为主的 React 应用，迁移不会改善核心体验，反而会增加双重运行模型和离线构建复杂度。
- Lenis 只接管电脑端主内容滚轮，并在触屏、减少动态或页面隐藏时自动停用；它不接管对话框或键盘焦点，也不在页面上制造控制器。
- React Flow 只承载原本就需要解释的三类真实流程。节点文字来自正式协议，页面不允许为了证明用了图表库而制造指标、示例资产或可拖动的“演示工作台”。
- 没有加入后处理 Bloom。首页已经用几何、材质与局部光照实现轻微闪亮；全屏 Bloom 会重新带来用户明确不喜欢的脏雾和强光晕，并增加 GPU 成本。
- 没有使用 React Three Fiber 重写已经稳定的 Three.js 场景。它是成熟的 MIT 开源方案，但当前直接 Three.js 的资源释放、动画循环和交互边界清晰，重写没有用户价值。

后续只有在出现明确需求和可验证收益时才增加这些能力。

## 8. 离线、电脑窗口适配与可访问性

- 根入口 `dashboard.html` 只跳转到 `dashboard/dist/index.html`；最终用户不需要终端、本地服务或网络。
- Agent 引导安装必须在桌面或系统等价的明显位置创建“Agent Carry 看板”入口，并让它指向正式安装目录中的根 `dashboard.html`。不能把根网页单独复制到桌面；快捷方式可在路径或系统变化后重建，不属于正式资产真源。Windows 验收必须使用当前 Shell／Explorer 认可的已知桌面位置，不能拼接用户主目录；入口还要经系统能力回读目标和工作目录，并从入口实际观察到看板主要界面，单纯“命令返回成功”不算完整通过。
- 构建产物把应用脚本与样式内联；四个字体面（正文可变字重、展示可变字重、代码 Regular／Bold）、`snapshot.js` 和许可证包保持本地同级资源，不访问 CDN，也不依赖用户操作系统是否安装某种中文字体。
- 当前验收基线是在 Windows 的现行 Edge／Chromium 内核中通过 `file://` 运行；现行 Firefox 与 Safari 是兼容目标，但在完成对应平台实测前不能写成“已验证”。
- 不注册 Service Worker；自动与手动重新读取都会给 `snapshot.js` 附加时间戳查询参数，避免浏览器缓存把旧快照误当成新状态。
- 看板只承诺电脑端使用，正式目标宽度为 1024px 及以上。低于该宽度的紧凑导航和文字流程只用于电脑窗口临时缩窄时防止界面崩坏，不构成手机或平板支持承诺。
- 可见界面文字不得小于 12px，且 12px 只能用于低优先级短元数据；说明与连续阅读文本通常应为 13–17px。不能为了塞进窄窗口而把文字压回 8–11px。
- 主要按钮至少提供 44px 左右的触控空间；图标按钮有可读标签或 `aria-label`。
- 分类使用真正的 Tab 语义，页面入口使用 `aria-current`，弹窗由 Radix 管理焦点，页面提供跳到主要内容的链接。
- 所有文本必须允许合理换行；真实资产标题和说明不能依赖演示长度。
- 监听 `prefers-reduced-motion`：关闭非必要进入动画、平滑滚动和星体连续运动；静态信息与导航仍完整可用。
- 首页“创建我的助手”或“继续第一件事”是每天最先使用的操作。它可以有低强度呼吸与掠光来提示“从这里开始”，但不得跳动、持续抢夺注意力或增加控制按钮；减少动态模式下自动变为静态按钮。
- 页面隐藏或 Three.js 区域离开视口时，连续渲染自动暂停；重新可见时恢复。用户没有暂停、旋转或重置 3D 的实际任务，因此界面不显示这些控制器。
- WebGL 初始化失败或运行中上下文丢失时，三维区必须降级为二维行星、轨道／卫星提示和明确说明；下方可访问分类坞仍须可用，不能让首页空白。验收同时覆盖初始化失败与 `webglcontextlost`。

## 9. 扩展规则

新增资产类型或全局动作时，应按下面顺序处理：

1. 先确认它是否属于正式产品语义，而不是某个宿主的临时能力；
2. 更新正式 Schema、地图或协议；全局动作以 `core/maps/dashboard-actions.toml` 为真源；
3. 更新快照生成规则与数据投影；
4. 在 `dashboard-config.tsx` 中加入稳定分类和导航关系；
5. 提供模板空态、真实数据态、字段缺失态和长内容态；
6. 如果按钮会引导真实操作，登记稳定 `action_id` 和完整请求，不在网页里直接执行；
7. 验证离线、常见电脑窗口、键盘、减少动画、无外部请求和控制台无错误；
8. 跟随 `core/maps/component-map.toml` 更新升级清单与公开文档。动作只是修改标签或请求正文时，同步正式登记表与前端兜底；只有动作投影字段或结构变化时才修改快照 Schema。

不应因为增加一个条件触发、治理日期或宿主能力，就把完整规则塞进启动上下文或看板快照。

首页和“当前状态”的“当前可见可携带内容”数字统计七个内容组在快照中的可见条目；隐藏待办仍保存在正式资产中，但不计入这个界面数字。模型、本地扩展、缓存和可重建索引不计入。单独的“随身资产”页面只统计该页管理的记忆、固定流程、能力与经验四组。

## 10. 验收基线

每次看板变更至少检查：

- `npm run build` 成功，`dist/index.html` 能直接通过 `file://` 打开；
- 正式模板显示真实空态，不含维护者身份、演示资产或具体治理日期；
- 私密维护夹具中的七个内容组加当前模型状态、长标题、长说明、完成／隐藏待办和缺失说明都能正确展示；模型不得计入可携带资产；夹具不得进入公开 `main` 或安装包；
- 如果 README 提供在线演示，Pages 候选必须复用当前正式 `dist/index.html`，显示纯虚构演示提示，使用合成快照，并通过界面摘要、文件集合和远端实际页面回读；看板改变后旧 Pages 产物不得继续冒充已同步；
- 五个入口、Hash 深链接、浏览器前进后退、搜索、详情与复制请求可用；
- 安装验收能从桌面或系统等价入口打开根 `dashboard.html` 并进入完整离线看板；入口不能依赖源码目录浏览、终端、本地服务器或 npm；
- GitHub 私密备份、本地隐私迁移、同机 Agent 接入和整套换机迁移保持边界清楚。GitHub 私密备份必须先给出本地检查结果和仓库预览，确认后才允许创建或推送到本人账号下的 `private` 仓库且默认不添加协作者；本地隐私包不得上传；同机换 Agent 不得默认复制整套资产；整套换机必须保持主体包、隐私包和恢复校验说明分离。复制文本必须包含秘密凭据和额外接收方边界，绝不能把真实凭据复制进去；
- 快照中的任何 `actions` 字段都必须被前端忽略；全局动作只能由正式登记表与同步构建的离线镜像提供；
- 1024×768、1366×768、1440×900 与 1920×1080 等常见电脑窗口没有横向溢出；
- 逐页检查计算后的实际字号：可见 DOM 文本不低于 11px，正文和主要操作保持既定语义层级；导航说明、按钮文字、状态和对话框不得因放大而被意外截断；
- 键盘焦点可见，减少动画模式可用，控制台和页面没有错误；
- 页面没有外部网络资源，也不会因重新读取本地快照而重载整页或重建 Three.js 核心。
- `font-manifest.json` 中四个字体面的文件、SHA-256 与 OFL 1.1 均匹配，生产依赖许可证清单与当前锁文件一致；旧字体不得作为未使用负担残留在分发包。
- `source-code/source-components.json` 中每个改写源码文件、固定上游提交、版权与许可证摘要可核对；任何新增二进制素材都已登记或被门禁拒绝。
