# AI Carry 产品身份与旧名兼容

本协议只在产品改名、安装、升级、迁移、发布或名称残留审查时加载。普通启动和普通任务不加载它。

## 当前身份真源

- 当前用户可见名称：`AI Carry`。
- 当前产品 ID：`ai-carry`。
- 当前核心 ID：`ai-carry-core`。
- 当前启动胶囊 ID：`ai-carry-startup`。
- 当前组件接口：`ai-carry.instance-component@1`。
- 当前模板新生成的产品自有字段、文件、快照和提示都使用当前身份。

`assistant.toml` 是当前产品名称、版本与兼容别名的机器真源；本协议解释迁移行为，不另建第二份版本真源。

## 旧名称怎样处理

1. `Agent Carry`、`agent-carry` 和 `AGENT_CARRY_*` 只在四类位置保留：真实历史、旧实例的创建历史、明确登记的兼容别名、仍未单独改名的 GitHub 仓库 slug。
2. 旧值可被读取、验证和迁移，但新建产品自有内容不得继续写旧值。
3. 旧实例的 `created_from`、用户正文、外来 Skill、历史回执和审计证据不因品牌升级被改写；它们记录的是过去或用户拥有的内容。
4. 旧组件登记表、组件清单和 `agent-carry.instance-component@1` 必须继续可解析。目标版本同时提供新接口和旧接口别名；现有组件原样保留，新组件使用新接口。
5. 旧专业扩展记录、旧隐私迁移包类型，以及旧宿主档案里的 `source = "agent-carry"`／`access_scope = "agent-carry-root"` 继续按需可读并原样保留；新记录只写 AI Carry 值。未知值不因改名而获得信任。
6. 新迁移和私密导出目录使用 `AI-Carry-Migration-*` 与 `AI-Carry-Private-Export-*`；已经存在的旧品牌目录只兼容读取，不能继续作为新输出名称。
7. 新看板生成 `AI_CARRY_*` 快照全局，并在本次主版本兼容期提供只读的 `AGENT_CARRY_*` 别名，防止升级切换时旧页面缓存只因一个变量名而失效。新页面优先读取新全局，也能读取旧快照。
8. GitHub 仓库当前仍位于 `Ww-Cooooo/Agent-Carry`。这个 URL 是已核实的外部位置，不是品牌漏改；仓库改名属于以后单独确认的外部动作。在兼容版本公开以前不得先改远端。

## 故障边界

- 普通启动或任务中只看到 `Agent Carry` 旧名时，先按已登记兼容别名继续；旧名本身不是身份损坏，也不能成为停止整个 Agent 的理由。只有当前产品自有输出仍在新写旧身份、证据互相冲突或用户要求审查改名时，才按需加载本协议。
- 无法迁移一个可推导的旧产品字段时，只隔离这次品牌切换或当前组件，保留源实例和候选；不得让原助手、对话和无关能力停止。
- 不认识的新字段原样保留，不通过删除、猜测或整库重写获得通过。
- 派生启动胶囊或快照漂移时，从已验证的合并真源重建；不得放宽真源校验。
- 只有会覆盖用户数据、暴露私密内容、改变实例身份或无法唯一判断外部仓库对象时，才需要用户决定。

## 发布前最小闭环

1. 全新模板只显示 AI Carry，并写入当前机器身份。
2. 一个包含学习资产、Skill、本机组件、专业工作区、私密层和未知字段的旧 Agent Carry 实例能升级到当前版本。
3. 旧实例 ID、`created_from` 历史和用户所有字节保持；产品版本、当前界面、启动胶囊与快照切换到 AI Carry。
4. 同一升级第二次零变化；中断只留下隔离候选并保持源实例可用。
5. 所有旧名称残留都归入历史、兼容别名或当前旧仓库 URL；未分类残留为零。
