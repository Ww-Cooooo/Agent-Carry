# 模型能力建议

Level 1／2／3 只描述一项任务大致需要的推理、工具和复核强度，帮助用户平衡成本与可靠性。它们不是身份、权限或可信度，也不能因为模型名称未知、界面标签不同或用户没有说“已切换”就阻断普通任务。

- **Level 1**：目标和边界清楚的日常任务、既有 SOP、首次创建执行器、普通召回和低风险局部修复。
- **Level 2**：有一定歧义的比较、候选提炼、多个相关资产之间的判断和中等复杂度迁移。
- **Level 3**：跨组件架构、高影响安全判断、复杂升级冲突、公开发布设计和需要独立复核的重要决定。

这些只是建议。经济型模型也应理解目标、发现局部错误并进行有根据的修正；强模型也不能仅凭等级获得联网、写入、删除、外发或发布权限。

## 使用方式

1. 先让当前 Agent 尝试完成边界清楚的工作，用实际结果和证据判断能力，不从品牌、价格、路由别名或自我感觉推断等级。
2. 如果任务确实超出当前 Agent 能力，说明缺少哪种判断、已完成什么、转交后要做什么；保留已有信息，不让用户从头重答。
3. 用户可以选择切换模型、交给另一个 Agent、缩小目标或稍后继续。切换是用户体验选择，不产生新的产品授权。
4. 高影响动作仍由用户意图、安全边界、来源真实性和可回退性决定；即使使用 Level 3，也不能绕过确认。
5. 普通首次创建、自然语言召回、学习回执、看板浏览和局部派生修复不要求模型等级证明。
6. 宿主能提供当前请求的实际模型信息时可以作为诊断事实记录；拿不到就写未知，不扫描进程、凭据或日志，也不让功能因此失效。

任务包或资产中的 `minimum_level` 是推荐提示。读取和召回时可以告诉 Agent“这项工作可能需要更多推理或复核”，但不能把字段差异、旧值或未知模型变成全局致命条件。
