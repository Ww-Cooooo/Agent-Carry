# 模型等级与切换

等级描述任务所需推理强度，不把某个模型永久绑定到一个等级。用户明确确认当前模型和等级后，以该确认作为本轮授权与预期真源；若宿主能提供当前请求的脱敏实际路由证据，还要把它与界面选择标签分开记录，不能用 `Auto`、第三方路由别名或辅助模型冒充实际执行模型。

- **Level 1**：默认工作层。适合目标清楚、验收明确、可按 SOP 或详细任务包执行的任务；允许正常思考、联网和自我修正，也可以按稳定资产协议报告学习信号、记录明确事件和更新无歧义证据，不是“机械照抄”。
- **Level 2**：适合提炼候选记忆、判断同类关系、改进能力、处理有一定歧义的范围／风险和中等风险复核。Level 1 无法确定时保持候选并交给本级。
- **Level 3**：适合实例化、助手核心架构、学习政策／Schema 变化、重要永久进化审核、跨组件升级、高风险决策，以及为 Level 1 制定完整执行计划。

## 切换规则

1. 当前模型不足时，明确说明需要哪个等级、为什么、切换后要做什么。
2. 等待用户明确回复“已切换完成”，并尽量记录模型名与平台；不能靠猜测或第三方路由别名替代用户确认。界面／配置选择与当前请求实际模型是两类证据：宿主若能直接提供请求元数据就记录实际值和观察依据；拿不到时明确写“用户已确认、实际路由未知”，不要为了查它而暴露进程参数、环境、授权头或日志。
3. 用户暂时不能切换时，经用户同意把任务写入 `instance/deferred/`；普通启动只保留所有定时事项的总数和唯一最早唤醒时间，不单独列出延期任务或读取正文。
4. 高等级任务完成后，若建议切回低等级，也要先告诉用户并等待同意；不得自行假定已经降级。
5. 同一型号可因平台、路由、推理强度和任务不同承担不同等级，不能做永久映射。
6. 对 Level 3 等关键任务，如果已观察到的实际请求模型与用户确认的选择明显不一致，先停止关键写入并说明差异；由用户修正路由、重新确认等级或选择延期。辅助模型参与摘要、检索或路由不等于主执行模型已经达到目标等级。

日常任务优先让 Level 1 完成；不要因为存在 Level 3 就把普通工作升级成昂贵流程。
