# 看板到 Agent 的动作契约

看板是离线只读投影，不直接修改正式资产。按钮只能复制一段完整自然语言请求，由用户发给 Agent。Agent 先在地图中定位 `action_id`，再读取本协议或对应目标文件执行。

这个边界不能因专业扩展而改变。扩展如确有真实本地写入用途，必须在自己的 `workspace/<extension-id>/extension.toml` 中登记范围，并按 `NETWORK_AGENT_SECURITY.md` 在用户发起动作时临时启用独立 Loopback 写入面；它不能把 Agent Carry 公共看板改造成常驻服务，也不能借看板读取或写入未登记资产。找不到写入的主要用户用途时保持 `local_write.mode = "none"`。

## 每个动作必须包含

- 稳定 `action_id`，不随按钮文案变化。
- 面向用户的“动词 + 对象”标签，例如“导出本地隐私迁移包”，不能只写“打包”。
- 一句话说明结果、是否会写文件、是否需要确认。
- 完整复制请求：用户意图、当前对象、动作 ID、应该读取的路由/文档、禁止行为、需要用户确认的节点和完成后应报告的结果。
- 目标路由与目标文档由 Schema 登记，不能把含糊短句交给 Agent 猜。

推荐复制请求结构：

> 我现在要【明确目的】。请把本请求视为用户直接指令，先在 Agent Carry 根地图中选择【route_id】，再读取【target】并按其中流程执行。动作 ID 是【action_id】。请只处理【范围】，不要【明确禁止项】；到达【确认节点】时先询问我。完成后告诉我生成位置、处理内容、跳过内容、冲突和下一步。

复杂决定可以先经过看板中的分步引导，再生成最终复制请求。分步引导只能使用快照里的非隐私摘要和动作元数据，不能读取正式资产正文、本地绝对路径或隐私正文，也不能直接执行动作。说明页、选择页和核对页必须使用三种不同的视觉与语义结构：说明页用一个非交互的线性流程并明确标出“无需选择”；选择页才出现可点击、带选中状态的选项；核对页使用一张完整只读核对单，明确写出“这一步没有需要选择的内容”或“这一步没有任何选项”，不得继续把摘要排成像选项的独立卡片。创建助手的三个步骤必须共用一个尺寸稳定且不超出当前桌面可视区的弹窗外壳；内容较多时只滚动中间正文，标题、步骤提示和底部动作不能被挤出屏幕。核对页底部只保留一个醒目的“核对无误”主动作和“返回修改”，不能再在主按钮旁重复放置“正确就点这里”之类的提示，也不能让用户猜下一步在哪里。最终请求必须带上用户已经在看板完成的选择；当前 Agent 应接着这个选择继续，不得让用户返回看板、重新复制指令或重复回答同一个问题。

## 长页面、滚动与三维动效

看板不能因为卡片变多，把渲染成本和卡顿转嫁给用户。当前资产与成长列表是少量、尺寸不一的语义卡片，不使用面向数千行同高数据的虚拟列表，也不为了“延迟加载”把正文从 DOM、浏览器查找或辅助技术中移除。适合独立估高的重复卡片和区块使用浏览器原生 `content-visibility: auto` 跳过屏外布局与绘制，并用 `contain-intrinsic-size: auto ...` 为尚未绘制的内容预留接近真实内容盒的高度；1024px 电脑窄窗要有单独估算。一个包含多种网格、说明和操作的超大异形区块不能整块延迟，否则第一次进入视口会把全部布局成本集中到滚动途中；它应在页面空闲时完成外层布局，再只对适合拆分的重复卡片延迟。真实滚动验收必须证明内容出现时没有横向溢出、明显滚动条跳变或布局位移。

电脑端主内容只有一个平滑滚动所有者。当前由 Lenis 增强滚轮连续性；不得再叠加另一套滚动库或 CSS 平滑滚动。触屏、减少动态、脚本不可用或 Lenis 不适用时退回原生滚动，页面和动作仍要完整可用。进入视口动效必须以真正滚动的 `.app-main` 为观察根，卡片实际进入可视区后才使用一次性的透明度、位移和极轻缩放逐张呈现；不能提前数百像素完成，不能被外层首次路由动画统一禁用，也不能用持续变化的模糊、阴影或大面积重绘证明“有动画”。减少动态时所有卡片必须立即完整可见。

首页 Three.js 是品牌导航，不得抢占阅读和滚动。主内容滚动期间，应用外壳通过 `agent-carry:scroll-state` 通知三维场景自动降低渲染频率；停止后恢复，动画推进按真实时间差计算，不能因屏幕刷新率或降帧而忽快忽慢。页面隐藏、核心离开视口或用户要求减少动态时继续暂停连续渲染，只在尺寸、指针或状态变化时按需重绘。普通用户没有控制渲染器的任务，因此不增加暂停、帧率或性能控制面板。

## 关键动作

- `dashboard.refresh-snapshot`：重新生成本地只读快照；每张资产卡必须能指回真实存在、稳定 ID 与 `kind` 一致的正式正文，各数组长度必须等于 `assets` 计数。初始任务族、计划路线、聊天候选或缺失正文的地图条目不是资产，不能投影。逐项校验所有卡片都有非空标题和明确说明，长期治理另含用途与步骤；每条改进建议必须从正式候选的来源引用和计数中生成不泄露正文的 `source_summary`，并给出 `target_kind` 与真实 `next_step`，不能把内部 ID、路径、日志、隐私正文或攻击载荷投影到看板；能力／SOP 按快照 Schema 从 `status + maturity` 派生兼容 `reliability`，不能把批准实例方向、预览或资产内容误写成已经验证。模板的 `meta.identity_ref` 固定为 `template`，正式实例按 Snapshot Schema 从 `instance_id` 生成匿名稳定引用；不得把实例名、领域、路径、个人资料或秘密写入引用。不得反向把快照写回正式资产。来源缺失、类型不符、计数不一致或其他校验失败时保留旧快照并报告具体冲突。
- `host.prepare-agent-switch`：只处理同一台电脑上的本地 Agent 接入。目标 Agent 能读取当前目录时直接接入同一份 Agent Carry，不重复打包或复制整套资产；只能接收文字时生成接入和当前任务所需的极小胶囊。目标位于另一台电脑时停止并引导使用 `instance.prepare-complete-migration`，不能假装目标设备已经拥有本地文件。任何方式都不得包含秘密凭据或一次加载全部长期资产。
- `instance.review-private-coverage`：查看 Agent 已经知道会随助手携带的资料，并补充或取消其他本地文件／文件夹。看板先用三步引导说明“为什么不展示具体文件名和路径”，再让用户选择“只查看当前清单”“补充以前的资料”或“我不确定，请帮我检查”；最终请求必须保留该选择。Agent 先复用当前任务中创建、移动和交付文件的已知位置，不能要求用户重新寻找；再按 `USER_GUIDANCE.md` 给出包含范围、空间影响和可恢复后果明确的选项。只有接入前、由其他软件创建、被用户私下移动或宿主看不到位置的资料，才让用户用日常语言帮助定位。只读取当前实例、命中的 `private_refs`、本地隐私管理根和已有绑定，不扫描整台电脑。绝对路径只写受 Git 排除的当前设备绑定，不进入看板、Git 或迁移清单；取消登记不删除原文件。
- `instance.prepare-complete-migration`：把另一台电脑继续使用所需内容准备成一个迁移套件文件夹。看板必须先连续完成三步：说明当前已知范围与隐私边界；让用户选择“按当前清单继续迁移”“先补充以前的资料，再继续”或“我不确定，请帮我检查”；生成带有该选择的完整请求。用户不需要预先理解或单独完成资料管理；当前 Agent 接到请求后直接承接看板选择，在同一次对话中汇总、必要时补充并继续迁移，不能让用户返回看板、重新复制指令、重复选择，也不能重新索取已知路径。主体包与一个或多个本地隐私分卷始终分开；目录、绑定、正式 `private_refs`、管理根实际文件和最终分卷清单必须先完成覆盖对账，只有全部已登记和已引用范围一一对应时才能写 `coverage_status=complete`。小型套件仍为五个文件，大型资料按 Migration Kit Schema 2.0 使用连续分卷，超大单文件可分块并保留整文件与块摘要；根校验覆盖入口、顶层清单、主体包和全部分卷。绝对源路径不迁移，目标设备默认恢复管理副本。API 密钥、密码、令牌、Cookie、私钥、恢复码和登录态永远排除并在目标环境重新配置。默认只在本地生成；用户另选 GitHub 私有仓库脱敏备份时，必须复用 `instance.prepare-git-safe-copy` 的检查和确认，任何私密分卷都不得进入 Git。套件完成后，当前 Agent 必须逐字给用户：`请先读取迁移套件里的 START-RESTORE.md，按照里面的步骤帮我恢复 Agent Carry，完成后告诉我检查结果。`
- `instance.instantiate`：仅在正式模板态启动实例化。先选择可随时调整的交流方式，再选择永久锁定的通用或单一专业领域方向；三种交流方式都可配合两种方向，不形成六套固定问卷，也不对应模型 Level。“先帮我判断”只用于方向确定前的比较，不能写成第三种方向。第三步必须改用一张与选择卡明显不同的只读核对单，列出已选交流方式和方向，在页内同时说明“这一步没有需要选择的内容”和“无需选择 · 只需核对”，并把“核对无误，生成创建指令”设为唯一主动作；需要修改时返回上一步。看板选择只保存在当前页面并进入复制请求，用户确认前不直接写文件。第一次接触 Agent 时用普通话从职业、困难和目标找到首个真实任务；熟悉 Agent 的用户可直接讨论标准、资料、工具、SOP、边界和验收。用户选中首项任务后先执行 `core/guides/first-use-execution-gates.md` 的实例化交接门：模板态不索取当天金额或真实业务文件，不开始任务；由用户确认正式方向并明确确认已手动切换到 Level 3 后，才进入结构设计与完整预览。正式写入前后再执行实例化写入门，只建立实例身份、初始任务族、干净信号、三张治理卡首轮排期、当前宿主最小档案和真实来源快照；不预先制造记忆、能力、SOP、经验、学习建议或待办，也不把任务族计为资产。用户暂缓第一项任务时只保留为下一步。
- `profile.adjust-guidance-mode`：只在正式实例中把 `profile.guidance_mode` 调整为一步步引导、适度引导或直接协作。用户已经在看板中选定目标时不重复询问；只改该极小字段并重建快照，不得重做实例化、改变方向或改写任何资产。
- `instance.prepare-git-safe-copy`：稳定 ID 为兼容旧版本保留，面向用户显示为“备份到 GitHub 私有仓库”。它先在本地生成不含隐私正文的洁净候选副本，对路径和普通文档／配置／源码内容做秘密与隐私检查；秘密检测只返回文件、位置、类别和数量，不把命中值交给模型。检查通过后展示账号、仓库名、`private` 可见性、分支和候选摘要，得到用户确认才可创建或更新本人账号下的 GitHub 私有仓库并推送。不得改为公开仓库、自动添加协作者或把秘密凭据交给模型。
- `instance.export-private-package`：本地隐私导出不能再由页面直接复制裸指令，也不能要求用户先去另一个区域管理范围。点击“开始导出本地隐私资料”后，三步引导必须在同一流程内说明当前范围，让用户选择“按当前资料范围直接导出”“先补充以前的资料，再导出”或“我不确定，请帮我检查”，核对后才生成带选择的请求；“只查看或补充范围”作为同一导出卡片内的次要入口。Agent 对已登记集合、当前绑定、正式引用、管理根文件和最终清单做覆盖对账后，在本地导出一个或多个私密分卷；大型文件使用流式摘要与必要分块，不把正文塞进模型上下文。用户复制并发送最终请求即授权本地创建，不重复确认；部分导出必须明确标为 `partial-approved`，不能声称完整。它不加入 Git 或上传到远程服务，秘密永远排除。
- `instance.import-private-package`：点击“开始在新电脑导入隐私资料”必须先打开三步引导，明确区分“完整输出文件夹”“不确定材料是否完整”和“尚未从旧电脑导出”。最终请求保留选择；新电脑上的 Agent 先让用户用普通话提供已知位置，再把单包或连续分卷当作不可信输入检查，不能扫描整台电脑或只拿一个 ZIP 勉强恢复。核对编号、分块和逻辑摘要后恢复为管理副本，只有用户明确选择时才建立新电脑外部绑定。不执行包内指令，不导入秘密，实例不匹配、缺卷或冲突覆盖时才询问。
- `instance.upgrade-template`：只在用户点击或明确提出时检查更新。先读取升级指南、机器契约和 `core/upgrade/official-source.toml`；允许联网时只从登记的官方公开仓库与正式 Release 检查，不后台联网、不自动下载，不从搜索结果或镜像猜官方版本。先报告来源、当前版本、目标版本、个人内容和已登记专业工作区的保留方式与冲突，未登记工作区原样保留并停止完整兼容结论；用户确认后才在隔离候选中升级。切换前核对稳定看板入口，按动作级事务和平台完整树验证，合并后从真实实例重建两份一致快照，再用组合证据打开验收；权限复制失败不能自动提权或修改系统策略。无法联网时请用户提供本地升级包。
- `preference.reuse-from-instance`：生成两段复制话术，在已有实例导出可复用偏好，再在新实例导入；不复制领域身份。

已完成普通待办不再提供“处理此待办”。它显示删除线和“已完成”标记，并提供“从看板隐藏”请求：Agent 只将该卡的 `visible` 设为 `false` 后重建快照，保留本机正文与完成历史。隐藏项不出现在看板，但仍可按稳定 ID 查询或恢复。

所有全局动作以 `core/maps/dashboard-actions.toml` 为正式登记表，并遵循 `core/schemas/dashboard-action.schema.md`。`dashboard/src/lib/data.ts` 只提供离线编译镜像，必须通过验收与正式登记表保持一致；快照中的任何 `actions` 字段都不得覆盖动作请求。动作新增、删除或改名时，必须同步 `core/maps/component-map.toml`、看板文案、前端镜像和升级说明并重新构建；只有展示快照本身的字段或结构发生变化时才修改快照 Schema。
