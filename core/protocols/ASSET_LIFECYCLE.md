# 记忆、能力、SOP 与经验生命周期

本协议只在任务出现学习价值信号，或创建、修改、激活、验证、复核、归档、清理正式资产时读取。普通任务只读取已经路由到的具体资产，不加载本协议、候选清单或全库证据。

稳定规则下的任务结束价值判断、明确事件去重、用户直接授权写入和现有资产证据更新可以由 Level 1 按本协议执行。关系、范围或风险存在歧义时，Level 1 只保留当前任务内观察并交给 Level 2，而不是猜测；只有用户已经选择“先观察／留下”，或能够验证这是获批旧候选的迁移，才可保留持久候选。修改本协议、Schema、实例学习政策、核心架构或处理高影响永久冲突属于 Level 3。不能把整个学习系统长期交给 Level 1 自行改写。

## 1. 资产角色与唯一所有者

- `memory`：用户事实、稳定偏好、长期约束和领域知识；`subtype=habit` 专门表示用户可见、可纠正、可停止沿用的沟通或工作习惯，仍然属于记忆，不另造一套资产体系。
- `capability`：可迁移的判断方法、操作能力或解决问题模式。
- `sop`：有明确目标、触发、输入、步骤、分支、风险、验证和完成标准的可复用流程。
- `experience`：真实任务发生过什么、哪里失败、如何修正及哪些结论可复用。
- `experience`／`host-execution`：某个宿主如何满足可携带能力或 SOP 的执行需求，只是可替换参考。
- `evolution-candidate`：尚未完成授权、证据、风险或冲突判断的新增、修改、替代、关联、归档或删除建议。

同一事实只设一个正式所有者；其他资产通过稳定 ID 引用，避免复制多份后互相矛盾。能力和 SOP 正文拥有可携带语义，宿主执行经验不得反过来修改其目标、安全边界或完成标准。

跨会话信号卡只累计“何时需要检查”的小型动态证据，不是资产正文，也不产生授权。信号达到条件后，由本协议进行来源、独立性、风险、成熟度和冲突判断。

## 2. 有价值小阶段与任务结束时判断内容是否值得保存

一个可独立核对的小阶段完成、任务结束、用户纠正、显著失败后成功修正、重复工作方式出现或用户明确要求记住时，只做一次轻量判断。用户说“结果正确”“这次做对了”表示结果需要核对；说“以后继续这样”“以后可以继续使用”“保存这套方法”还表示希望这项可复用内容进入长期处理，不能只在聊天中口头答应却不判断是否需要写入：

1. 未来真实任务是否可能复用；
2. 是否改变用户事实、偏好、边界、判断方法、能力、SOP 或重要失败恢复；
3. 是否有可核对来源或执行证据；
4. 是否只是一次性参数、临时路径、界面状态、普通步骤、工具日志或已有内容的原样回显。

四项都没有长期价值时安静结束：不创建空候选、不写动态状态、不询问固定的“是否形成 SOP”。命中价值信号后才读取本协议并进入后续步骤。

### 2.1 Agent 主动发现，用户只判断“要不要以后继续”

默认用户可能不会主动说“把它保存成记忆”或“形成 SOP”。当任务出现下列真实信号时，Agent 应在当前小阶段结果已经交付或修正完成的自然停点，使用用户当前交流语言、用容易理解的话主动说明新增发现：

- 用户明确纠正了表达方式、工作顺序、质量标准或边界；
- 同一种选择、格式、判断或操作在不同任务中重复出现；
- 一套做法完成真实任务并通过结果核对，未来很可能再次使用；
- 用户表示“这次对了”“以后照这个来”“上次的办法更好”，但没有使用内部资产术语；
- Agent 发现已有资产没有被日常说法命中，或用户误以为必须记住准确名称。

询问必须聚焦用户意图，不把内部分类题交给用户。例如：

> 我注意到你连续几次都希望我先给结论，再补必要解释。以后我可以默认这样回答。要把它作为你的长期习惯留下吗？你也可以说“只在工作汇报里这样”或“这次不用记”。

对于流程类发现，应说清以后在哪类任务中能复用、这次是否已有真实验证，再问是否留下；不要问“要不要形成 SOP、能力还是经验”。Agent 根据内容用途决定内部类型，并在预览中使用用户当前交流语言解释：“我会把它保存为一套可重复使用的做法”“我会把它保存为你的沟通习惯”。

阶段报告与持久决定是两件事。一个任务可以在几个真正有复用价值的小阶段分别报告新增发现，但同一组连贯内容最多在自然停点集中提出一次保存决定；普通机械步骤、同一结论的反复修正和没有验证的猜测不报告、不重复问。报告必须独立于长篇结果：尚未保存时使用“这一步还在学习”的短表；只有正式正文与路线原子写入、严格回读、日常说法召回全部通过后，才能使用“这一步我学到了”的短表。只建立观察候选、保存后召回失败或事务仅形成预览，都继续如实标为“还在学习”；具体短格式按 `core/protocols/USER_GUIDANCE.md`。

询问前的发现只保留在当前任务里，不得创建候选、正式资产、信号或提醒。为使普通 Codex、Claude Code、Trae、WorkBuddy 等宿主能够跨一轮聊天恢复同一项选择，生产入口可以在 `.assistant-local` 写一条有 TTL 的本机操作回执；它只含 nonce、仓库／实例绑定和内容／状态摘要，不含候选正文或未授权语义内容，不进入启动上下文、迁移包或公开版。它不是学习资产，也不是对发现内容的持久化，不会自行推进；用户不回答时，由下一次相关入口或维护定向清理，不运行后台任务。因此“不回答／不保存为零写入”专指候选、正式资产、信号、提醒和其他语义写入为零，而不是虚假承诺磁盘上连这条短期无语义操作回执也不存在。

用户选择“不保存”时丢弃本任务观察并清理对应操作回执；选择“先观察”时，才以一个精确可恢复事务建立最小 `evolution-candidate`、候选索引、学习信号以及 public／dist 两份相同看板快照。选择“以后提醒我再决定”时，同一事务再加入时间投影；Agent 当场用用户当前语言说明保存了什么以及怎样用日常说法取消。用户没有回应时不得把沉默当作同意，也不得创建未授权候选。若用户拒绝保存这条极小记录，则候选、索引、信号和提醒全部为零，不能制造没有来源正文的“裸提醒”。

模型或宿主主动发现后，只有在询问前已经完成正式 Schema、秘密边界、同类去重、模型等级、路径、地图预算和快照闭包预检，并向用户展示与精确正式字节摘要绑定的完整预览（内容、适用／不适用范围、未来动作确认门、初始成熟度、纠正／停用方法、写集合与整体回退）时，“留下”才是一轮确认：该回复直接授权正式资产、直接路线和两份看板快照的原子事务，不再强迫用户先建候选后重复确认。保存不等于执行未来动作，也不把一次宿主观察冒充为成功验证。若关系不是明确 `new`、存在相似／冲突、风险或 Schema 不清、等级不足、预算超限或无法原子闭合，必须在用户选择前把选项标成 Level 3 定向复核，不能等用户说“留下”后才假装已保存或制造死候选。

用户原消息已经明确说“记住这个”“以后这样做”时，也必须进入上面的精确预览，让用户作一次真实选择。当前通用、提示词优先母版没有模型不可访问的消息角色认证通道，因此不得导出或消费任何声称能由普通 JSON 证明用户身份的 direct-user 回执；多一次精确预览选择是必要的宿主行为门，不是密码学身份认证，也不是重复追问模糊问题。事务代码只能绑定预览、选择与写集合，当前宿主仍须真实展示并等待用户回复。风险分级学习政策只能按第 5 节调整候选的验证和复核顺序；无论风险高低，进入可撤销试用或其他正式资产前都要用户明确确认具体内容和适用范围。

普通提示词宿主进入这条路线时，只使用 `dashboard/scripts/learning-save-cli.mjs` 作为学习保存入口；`learning-capture-cli.mjs` 是底层维护与已有事务恢复接口，不用于从自然语言新建正式内容。Agent 只提交标题、用途、触发、范围、步骤、失败处理和完成检查等简短业务含义；产品确定性生成 ID、路径、正式 frontmatter、零成熟度计数、摘要、预览绑定和原子事务。`prepare` 返回完整自然语言预览与可直接复用的 `confirmCommand`；用户作出一次选择后，Agent 只把用户原话交给 `--user-reply`，产品同时识别选择并保存同一条确认回执，不再要求模型猜 `choice`、重复编写 `message` 或手写内部字段。产品返回的自然语言预览必须完整展示会保存的含义、适用／不适用范围、步骤、失败与完成标准、初始未验证状态和未来动作边界；内部格式与精确字节摘要由产品绑定，不能要求用户或模型填写。产品负责执行、回读、失败整体回退和清理短期回执。格式或局部事务错误只暂停这一项保存，并明确说明错误、数据状态、仍可用能力和推荐下一步；不得拖垮对话或实例主体。

提示词宿主不能独立证明刚完成任务的结果时，来源保持 `unknown + closed-unverified`。这不妨碍用户在看过上述完整预览后，把一份关系明确为 `new`、Level 1、低风险、无秘密／设备路径、无成功与成熟度预领的内容保存为正式 `unvalidated` 资产；用户确认的是具体内容与范围，不是一次结果验证。外部内容、中高风险、关系或冲突不清、已有同类资产、未来动作边界不闭合时仍进入定向复核，不能借简短入口直写。

`subtype=habit` 是直接代表用户的沟通或工作习惯，必须让用户确认具体内容和适用范围后，才能成为正式习惯并显示在“我的习惯”中。模型推断或重复观察可以形成任务内候选并触发上面的询问，但“低风险可撤销试用”不能代替这次确认；用户选择“先观察”时继续保留最小候选证据，不建立自动沿用路线。

用户直接说“记住这个”“以后都这样”或明确批准某项修改时，Agent 应据此准备没有扩大原意的精确预览；用户在该预览中选择“留下”后，才形成正式内容授权，且不再重复追问同一内容。内容或范围仍有歧义时，只补问那个最小问题。内容授权仍不等于任务结果验证，也不能绕过隐私存放、外发、发布、删除和其他动作门禁。

第一项真实任务在实例化阶段只登记为任务族，不是预先形成的能力或 SOP。第一次完成后，结果和授权分别判断：只确认结果正确不自动授权新资产；用户同时要求以后继续使用或保存方法时，才按本协议创建正式资产。若任务已经通过 `RESULT_VALIDATION`，新能力或 SOP 可以从 `maturity=practiced` 和一次独立成功开始，但不能直接写成 `reliable`。

新资产正文的篇幅按任务复杂度和风险决定，不以章节数量证明认真。简单流程可以把模板章节合并为少量完整段落，但必须覆盖目的与非目标、触发与排除、输入缺失、步骤和关键分支、职责／权限边界、验证与失败处理、用户结果以及学习更新；不得填充空样板，也不得只把本轮聊天换一种说法保存。涉及资金、隐私、外发、权限或不可逆动作时，相关边界必须显式保留。

正式写入使用本次真实任务事件时间：`updated_at` 是本次资产写入时间，`last_validated_at` 是本次通过结果验证的时间，均带时区；无法可靠取得时留空，不能复用实例创建时间、治理锚点或旧快照时间。事件引用必须稳定去重，但不得以编造的精确时间补齐未知证据。

准备把学习结果正式写入、修改、迁移、替代、归档或删除前，命中 `core/protocols/COMPONENT_CHANGE.md` 的“实例正式资产与状态”路线，并用 `core/protocols/INSTANCE_EVOLUTION_COMPATIBILITY.md` 核对本次写集仍由原生资产层拥有、没有越界修改模板核心或形成未登记跨组件依赖。兼容入口不复制资产正文、不为每项资产创建组件清单，也不增加一轮用户确认；本生命周期继续唯一负责授权、风险和成熟度判断，共同质量协议负责根因、影响、可达性、数据保护、回退与结果验证。这些完整协议只在持久变更已经成立时加载，普通资产读取和没有长期价值的任务不加载。

正式资产准备新增、改变或删除 `private_refs` 时，再按需读取 `core/schemas/private-asset-catalog.schema.md` 与隐私迁移 SOP：只更新命中的目录项或旧引用，不加载整份私密目录。Agent 在当前任务中创建、下载、移动、整理或交付了文件时，复用工具结果中已经知道的位置和用途，不得随后要求用户重新寻找路径；再按 `core/protocols/USER_GUIDANCE.md` 判断用户是否希望这些资料长期随助手携带。用户已经明确说“以后还要用”“跟着助手走”或等价意思时视为直接授权，展示范围后登记本地绑定，不重复确认同一决定；意图不清时针对真实文件给出包含范围、空间影响、可重新生成性和临时使用在内的完整选项，不能只问“要不要保存”。没有长期携带意思的普通任务输出不自动登记。删除正式引用也不等于删除隐私正文或取消整个集合，二者都需要各自明确处理。

创建正式资产后，在实例领域地图新增一条 `asset_kind` 与正文 `kind` 一致、`id` 和低敏 `title` 与正文 frontmatter 一致、`target` 直接指向正文的正式路线。首项 `task-family` 是非资产导航：不能只给它追加关联 ID 代替正式路线，也不能原地改名冒充资产；它仍有独立导航价值时才保留，否则移除。随后从正式真源重建快照，使用本次真实生成时间并重新计算来源摘要；只改数组、计数或卡片而沿用旧 `generated_at`／`source_digest` 不算重建完成。持久变更完成前再做一次确定性可达性闭包：所有 `active`、`provisional` 或 `review` 的记忆、能力、SOP 与经验正文都必须能从实例领域地图按稳定 ID 直接找到，并且路线 `title` 与 frontmatter 一致；检查只读取地图与 frontmatter，只有缺口命中后才展开少量正文。

新建或修正资产路线时，至少记录一个用户真实可能说出的低敏 `trigger`，并根据已确认语义补充少量别名、对象、范围、条件和排除项。资产标题可以专业，触发语必须允许普通人不精确地表达目标。用户原话包含姓名、成绩、账号、金额、私密项目名或其他不应进入小地图的内容时，改写为不泄露正文但仍可召回的表达；不能把原始聊天复制进元数据。

## 3. 先匹配学习线索，不全量读取

为新学习生成小型检索特征：目标资产类型、`topic_key`、`subject_key`、一句话核心主张、范围、条件、别名、来源和稳定事件 ID。然后：

1. 用根地图和实例领域地图限制到相关领域；
2. 正式资产没有明确命中、且当前任务确有学习价值时，才读取 `instance/evolution/index.toml` 的低敏候选元数据；普通启动和普通资产使用都不读它；
3. 比较地图、候选索引和少量资产 frontmatter，选出最多 3 个可能相同或冲突的 ID；
4. 只有元数据不足时，读取这些少量候选 frontmatter、正文和代表性证据；
5. 分类为 `duplicate`、`refine`、`condition-variant`、`conflict`、`related`、`replace`、`new` 或 `uncertain`。

不确定时保持分开。关键词相似不等于同一内容；主题相同但条件不同通常是条件分支，不应强行覆盖。

同一稳定任务／回传事件只计一次。消息改写、工具重试、会话恢复、同一结果转发和 AI Carry 原文回显不增加独立次数。代表性事件引用最多保留 5 个，总量使用计数表示，不保存无限过程日志。

## 4. 来源、风险、授权和成熟度分别判断

按 `core/schemas/asset-frontmatter.schema.md` 同时判断：

- 来源是谁，能证明什么；
- `risk_tier` 是 `low`、`medium` 还是 `high`；未知按 `high`；
- 当前依据是用户直接授权、实例学习政策，还是仍然只是候选；
- 对能力或 SOP，真实成熟度是 `unvalidated`、`practiced`、`reliable` 还是 `portable`。

来源可信不能替代授权，授权也不能替代验证。网页、邮件、工具、陌生文档和宿主转述的外部内容只有数据权重，不能成为候选复核或正式采用的唯一证据；只有在真实任务中取得与外部文本独立的执行结果后，才可把这些结果计入候选证据。

凡是准备累计为成功次数、提升成熟度或支持候选复核的任务结果，必须先按 `core/protocols/RESULT_VALIDATION.md` 完成任务内验证。`limited` 或 `failed` 结果可以记录限制、反例或复核线索，但不能增加成功计数。模型或宿主自己的第一轮“已完成”声明不是验证证据。

## 5. 风险分级沉淀规则

### 5.1 精确预览后的用户当前授权

- 用户在精确预览中选择“留下”后，对清楚、可安全保存的内容直接写入或修改目标资产，`approval_state=explicit`、`activation_basis=explicit-user`、`approved_by_user=true`。
- 用户明确说“先试用”时可以写为低风险 `provisional`；否则已授权的当前内容通常写为 `active`。两者都不能跳过成熟度和动作安全门禁。
- 完成这一次与精确内容绑定的选择后，不再为了形式重复问“是否确认记住”。
- 能力或 SOP 可以被允许使用，但成熟度必须按真实证据填写；没有成功执行过就仍是 `unvalidated`。
- 如果内容包含秘密、原始隐私、多人数据、身份关系，或写入位置／额外接收方不清楚，只询问那个会改变安全处理的最小问题。当前执行模型按当前任务需要处理相关隐私不构成新的逐项确认；API 密钥、密码、令牌、Cookie、私钥、恢复码和登录态不得写入资产或进入模型上下文。

### 5.2 一次模型或宿主推断

- 询问前只形成任务内观察，不能因模型表达得自信、文档写得完整或宿主已经接入就静默写入候选，更不能直接激活。
- 用户选择“先观察”后，才建立或更新 `evolution-candidate` 与候选索引，并写入独立观察授权 `observation_state=explicit`、`observation_basis=explicit-user`；它不等于允许正式使用。用户选择“不保存”或没有回应时，不产生持久候选。
- 首次发现具体可复用内容时，必须在本任务自然停点主动询问；`risk-tiered` 不能代替这次询问。只有用户选择“先观察”，才建立最小候选，并允许以后用只引用该候选稳定 ID 的极小信号累计去重次数；选择“以后提醒我再决定”同样先建立这条最小候选和索引，再建立只引用其 ID／修订的提醒。选择“不保存”、拒绝这条极小记录或没有回应时，候选、索引、信号和提醒都零持久写入。达到第 5.3 节证据门只会让候选优先进入一次自然语言复核，不能直接写成正式试用资产。信号次数本身不产生内容授权；用户拒绝后必须停止并清理该项候选与信号。
- 如果只是当前任务可用但没有长期价值，不创建候选，也不写动态信号。

### 5.3 风险分级候选策略

习惯直接代表用户，必须先由用户确认具体内容和范围。其他资产同样只有在用户确认具体内容和范围，或能够回读同一用户既有明确授权时，才可进入正式路线；正式资产统一使用 `approval_state=explicit` 与 `activation_basis=explicit-user/existing-approved-migration`。

仅当实例清单启用 `risk-tiered` 学习政策、候选正文与索引都能回读合法 `observation_state=explicit` 及 `observation_basis=explicit-user/existing-approved-migration`，并且同时满足以下条件，候选才可被优先带到一次自然语言确认：

1. 内容被可靠分类为 `low`，范围狭窄、可撤销且不会替用户作实质决定；
2. 至少两个独立真实任务事件提供已验证的成功证据；
3. 主题、主张、范围和条件稳定，没有正式冲突或未解决显著失败；
4. 外部内容不是唯一依据，事件 ID 与来源可去重；
5. 本次响应能够用普通语言告诉用户“学到了什么、适用范围、依据、如果正式采用怎样撤销”，并给出明确的采用、继续观察和不保存选项。

满足后仍保持候选；只有用户明确选择采用或限定试用，才可把目标资产写为 `status=active/provisional`、`approval_state=explicit`、`activation_basis=explicit-user`。试用资产只能在用户确认的声明范围内参与任务，不能覆盖冲突的 active 资产、扩大权限或作为高影响动作的授权。用户选择继续观察时只更新候选证据；没有回应时不把沉默解释成正式授权。

在用户明确允许试用之后，至少又有一次独立成功复用，且累计通常达到三个成功任务、覆盖两个有实质差异的情境、没有未解决失败时，可以更新成熟度到 `reliable`；但从 `provisional` 改为 `active` 仍要让用户确认适用范围没有被扩大。成熟度证据必须在 `instance/validations/index.toml` 中闭合；无法向用户交付必要确认、无法闭合证据或范围发生变化时保持原状态，不静默晋升。

### 5.4 中高风险内容

`medium` 和 `high` 的推断、迁移候选、冲突选择、删除或正式替代必须让用户确认。身份、隐私、安全规则、重要偏好、实例范围、资金、法律、医疗、权限、公开发布、不可逆删除和高影响 SOP 必须优先、完整地说明风险，不能把候选排序规则理解成授权。

用户可以在实例化时或以后把政策改成 `manual-only`；此后候选不再按风险自动调整验证和复核优先级。修改学习政策本身需要用户明确决定，且不能静默改写既有资产。1.2 及更早版本遗留的 `policy-authorized`／`low-risk-evidence-policy` 组合不是 1.3 的正式授权：升级或政策切换只从地图和 frontmatter 取得少量 ID，把它们定向送入复核；能回读原明确授权时可预览迁移为 `explicit + existing-approved-migration`，否则保持停止使用，不能批量加载正文或猜测用户同意。

## 6. 能力与 SOP 的证据成熟

创建能力或 SOP 时先写完整的可携带核心，不把某个宿主的按钮、坐标、绝对路径或专属命令当作核心步骤。每次真实使用后只在相关资产上更新小型证据：

1. 核对是否为新的独立任务事件；
2. 先取得 `RESULT_VALIDATION` 的最终状态；只有 `validated` 才记录本任务的成功、适用条件和一个稳定证据引用；任务内重试和修正不重复累计，修正后最终成功最多按一个成功任务计；
3. 替换或压缩代表性引用，最多保留 5 个；
4. 根据真实结果调整范围、失败恢复和成熟度；
5. 有显著失败、环境变化或冲突时进入 `review`，而不是隐藏失败或全部推翻。

从候选生成能力或 SOP 时，必须按目标资产真正需要的理解、判断、安全和执行难度重新计算 `minimum_level`，不能机械继承候选审核所需等级。清楚、低风险、可验证的执行流程默认允许 Level 1；架构、政策、Schema、安全边界和其他重要决策仍由 Level 3 负责。

默认成熟度口径：

| 成熟度 | 最低含义 |
| --- | --- |
| `unvalidated` | 只有说明，没有一次真实成功证据 |
| `practiced` | 至少一次可核对的真实成功 |
| `reliable` | 通常至少三个独立成功、两个不同任务情境、范围稳定且无未解决显著失败 |
| `portable` | 先可靠，再跨至少两个真实宿主档案或一次实质环境变化，通过语义自适应成功 |

次数是检查门，不是机械评分；任务难度、风险、反例和证据质量可以要求更强验证。用户明确批准不会把 `unvalidated` 自动改成 `reliable`。

候选阶段的 `independent_event_count` 与 `distinct_context_count` 只说明受信宿主回执区分出了多少不同任务观察／情境，用于安排复核优先级；它们不是任务结果验证，也不继承为正式资产成熟度。用户采用后，新的正式资产从 `unvalidated` 开始。只有独立写入并闭合到 `instance/validations/index.toml` 的 `RESULT_VALIDATION` 记录才能增加正式成功／失败和成熟度；不能把候选观察次数直接复制成验证成功。

## 7. 宿主执行经验

当某个可携带核心第一次在当前宿主成功落地，且实现方法对以后复用有价值时，可以创建 `experience`／`host-execution`：

- 只记录语义能力需求如何映射到当前宿主、已验证方法、环境范围、限制、失效信号和回退；
- 通过 `portable_core_ref` 指回核心，通过 `host_profile_refs` 指向宿主档案；不复制核心正文；
- 不保存凭据、隐藏提示、无关设备信息、私人绝对路径或完整日志；
- 一次已验证成功只能在用户当次明确授权采用时进入 `provisional` 或 `active`，成熟度至多为 `practiced`；`risk-tiered` 只能让证据充分的低风险候选优先接受复核，不能替代这次明确授权。重复成功后才能标为 `reliable`；它永远不能标为 `portable`；
- 宿主、版本、权限或环境变化时只在使用该经验时复核，不轮询全部宿主经验。

任务使用能力或 SOP 时，先读取可携带核心；再从 `host_experience_refs` 的 frontmatter 中筛选当前宿主和环境，最多展开一个匹配正文。没有匹配经验不阻塞任务，宿主按核心要求重新规划并验证。

## 8. 自我修正与失败

模型可以在一次任务中观察错误、调整判断或路径并再次尝试，通常允许 3～5 次有根据的修正。每次修正应让用户能理解：原错误、判断原因、修改了什么、最终是否解决。

当任务命中结果验证门时，默认把其中 1～2 轮用于新的来源／契约复核；这些轮次包含在上述总预算中，不另起无限重试。只有最终验证通过才可把同一事件计为一次成功；没有进展或仍缺少会改变结果的依据时，按 `limited`／`failed` 结束。

错误或用户纠正是一次学习信号，不是自动写入长期资产的许可。处理顺序固定为：

1. 先依据当前任务的正式来源和用户反馈修正本次结果，完成与风险相称的验证；不能一边留下错误结果，一边只记录“以后注意”；
2. 再区分一次性失误、环境故障、工具／验证器故障和可跨任务复用的根因；无法确认时只保留本任务结论，不强行总结；
3. 只有修正后的结果已经验证、根因确有未来价值时，才生成**当前任务内**的小型学习特征并进入同类匹配；任务内预览至少说明适用情境、原失败、根因、正确替代、证据、范围与反例；
4. 在结果交付后的自然停点，使用用户当前交流语言说明未来用途并让用户选择“留下”“先观察”“以后提醒”或“不保存”。只有“留下”才进入正式资产判断；“先观察”建立可撤销候选；“以后提醒”在同一事务中建立候选和只引用该候选的有界提醒；不保存或未回应时不写 candidate、index、signal 或 reminder；
5. 获准处理后再根据真正用途把它沉淀为经验、记忆、能力或 SOP：任务经过与教训通常属于经验，稳定事实／偏好属于记忆，可复用判断属于能力，稳定步骤与分支才属于 SOP；用户可以直接纠正、缩小范围或撤回，风险、授权、成熟度和清理仍按本协议判断，不能用“已经犯过错”跳过门禁。

同一任务内的初稿、纠正、重试和验证只算一个稳定事件。没有复用价值的失误、临时调试输出和完整错误日志在任务结束后丢弃，避免把 AI Carry 变成错误记录仓库。

成功修正只有在判断值得长期保存、并取得本轮“先观察／以后提醒／留下”授权，或命中已有合法授权资产时，才形成持久候选、提醒或更新证据；否则只在当前任务中完成修正后丢弃观察。失败不得为了维持成熟度而忽略：对已经存在且合法命中的资产更新失败计数和限制；如果失败暴露核心逻辑错误、安全风险或范围失真，把资产转为 `review`，等待修订或用户判断。

### 8.1 用户主动分享为 Skill

正式资产的成熟度不等于分享授权。看板推荐只是只读建议，不接受脱敏处理，也不触发转换。只有用户明确提出“把这个方法转成 Skill”或同等意图时，才读取 `core/guides/skill-workshop-guide.md`：SOP 可作为主要来源；能力必须先证明包含可重复流程；经验先提炼成 SOP；记忆、习惯、偏好、身份和私密正文不得直接导出。用户不用预先手工脱敏；由 Agent 复制用户选中的方法，只在这份隔离草稿中自动完成隐私检查、脱敏、通用化和参数化，来源资产保持原样，转换成功也不改变其状态或成熟度。用户不转换不会产生待办、治理卡、红点或负面状态。

共享包默认只留在本地，不能因为用户允许生成就推定其允许上传、公开或发送。导出的本地索引属于实例资产，不进入普通启动上下文；共享目录不得携带来源资产 ID、实例身份或私密引用。

## 9. 清理、压缩与历史

- 不按“多久没用”单独删除。`expected_next_use` 保护低频但生命周期明确的重要资产。
- 在生成候选前过滤无价值噪声；完全重复只合并计数和代表性证据，不新建正文。
- 已拒绝、已合并、已解决、无引用且无复用价值的一次性低风险候选退出投影并删除或压缩，不能永久堆积。
- 当前有效资产、待复核资产和按需历史分开。普通变化的历史只保留旧结论、替代原因、时间范围和当前资产 ID；只有高影响、难恢复或确有审计价值的内容保留更多证据。
- 低风险、未获用户直接批准的候选和失效宿主经验可以在明确无价值时低打扰归档或删除。`evolution-candidate` 本身不能进入 `provisional`；达到试用门时创建正式试用资产并原子归档源候选。正式试用资产或宿主经验曾进入 `provisional` 后再归档时，在用户可见结果中说明并保留撤销／恢复路径。
- 用户直接批准的长期记忆、能力、SOP、安全规则和难恢复经验，永久删除或实质覆盖前取得用户确认。
- 正式冲突、明确替代、来源失效或超出实例方向时立即检查，不等待周期扫描。

## 10. 动态状态与启动边界

- 跨任务计数保存在候选或目标资产的小型 frontmatter；可参与同类匹配的候选另投影到 `instance/evolution/index.toml`，但该索引只在学习信号命中后读取，普通观察和普通启动都不加载正文。
- 只有达到检查条件、出现冲突／不确定、需要用户决定或事务中断时，才把稳定 ID 和短路线投影到 `instance/maps/signal-map.toml`。
- 用户明确要求稍后提醒候选时，才写 `remind_at`、同步非启动时间索引和最早唤醒聚合；提醒必须引用可回读的最小候选 ID 与修订，不能脱离候选保存主张、摘要或哈希。没有提醒要求就不创建日程。
- 资产或地图本来发生变化时顺手更新计数、引用和预算，不做后台全库扫描。
- 普通候选变更按“候选正文 → 进化索引 → 必要信号投影 → 看板快照”作为一个可恢复动作更新；正式资产变更按“目标资产 → 领域地图 → 必要信号投影 → 看板快照”更新。候选索引任一投影字段变化时，候选正文 `source_revision` 必须在同一事务中恰好加 1，索引条目和引用该候选的信号随之回读同一修订；撤销观察授权、升高风险、更新证据次数／时间或移动来源都不能沿用旧修订。投影未变时修订保持不变。`provisional` 在地图中明确标为试用，`candidate` 只进入进化索引，不混入普通稳定路线。索引的结构、预算、计数、清理与 `rebuild-required` 语义以 `core/schemas/evolution-candidate-index.schema.md` 为准；中断时由统一触发事务定向恢复。

候选晋升、合并或取代正式资产时，必须使用一笔原子事务，不能留下“候选和正式资产同时代表同一件事”的双份状态：

1. 创建或更新正式目标正文并回读稳定 ID、kind、状态、授权和内容摘要；
2. 创建或更新与目标一致的正式领域路线并完成可达性闭包；
3. 将源候选标为 `archived`，写入 `resolution = "promoted" | "merged" | "superseded"` 和 `resolved_to = "<formal-id>"`，或者在用户授权永久删除且保留审计证据后删除；不得继续把它当活动候选；
4. 从活动候选索引和学习建议投影移除源候选，重新计算 `candidate_count`、`indexed_count`、`active_count`、溢出状态与必要信号；候选历史仍存在时只按稳定 ID 按需读取；
5. 从正式真源重建 public/dist 两份快照并回读：正式卡片只出现一次，学习建议不再出现源候选；
6. 任一步失败都回滚目标、路线、候选、索引、信号和双快照到事务前状态。相同事务第二次执行必须报告 `updated=false` 且完整相关文件逐字节不变。

`learning-capture` 已持久化的 `awaiting-level3-learning-review` 交接是正式晋升的可验证授权入口：载荷 ID／引用／摘要、候选修订和 `formal_preview_digest` 必须全部回读一致。正式正文、适用范围、排除项、风险和未来动作确认门逐字节未变时，晋升事务复用原“留下”授权，不再重复询问；任何实质变化都返回需要新确认。跨进程事务把精确写集合、每步摘要、全部 preimage、仓库／实例绑定和恢复证据封存在被 Git 忽略的 `.assistant-local/learning-promotion-transactions/`；普通 CLI JSON 只提供稳定引用和摘要，不能证明当前用户身份，也不能替代本轮已展示精确预览后取得的交互回执或上述已验证交接。该交互回执只是提示词优先宿主的行为边界，不是密码学身份认证；任何代码都不得因此获得自行代替用户确认的 direct-user 入口。`prepared` 可过期清理，已进入 `planned` 的部分前缀或漂移必须保留以供恢复／回滚，不按 TTL 删除。
