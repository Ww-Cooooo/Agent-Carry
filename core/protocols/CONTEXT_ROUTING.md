# 渐进上下文路由

本协议只在路由异常、能力找不到、上下文过载或维护路由系统时读取。普通任务只执行 `BOOTSTRAP.md` 和地图元数据。

## 固定结构

Agent Carry 只有三层：

1. 根地图：判断任务属于哪个类别。
2. 分类地图：查看小型路由元数据，选出候选能力。
3. 目标正文：读取真正执行任务所需的协议、SOP、能力、记忆或指南。

不得增加“必须先读的第四层”。目标正文也不得为了声明“何时不读我”而进入普通上下文；是否读取必须由上一层地图的触发元数据决定。

`core/maps/trigger-registry.toml` 是维护盘点，不是普通请求的新路由层；`instance/maps/time-trigger-map.toml` 是日期命中后的非启动索引，也不是每次必经层。普通请求仍是根地图 → 分类地图 → 目标正文，只有恢复、到期或当前事件确实命中时才旁路读取相应小型状态。

动态启动胶囊中的 `instance/maps/signal-map.toml` 是当前运行状态的极小投影，不是内容发现层。它只能指向根分类和路线，不能绕过根地图、分类地图直接扩展为第四层，也不能携带完整规则或资产正文。

## 混合选择

- 明确关键词、稳定动作 ID、文件类型或实例方向可由确定性规则直接匹配。
- 实例资产路线可用 `asset_kind`、主题、对象、别名、范围、条件和关联 ID 做小型候选漏斗；这些字段只用于发现，不能代替目标正文的执行规则。
- 规则得到多个合理候选或无法判断语义时，才让模型在候选元数据之间做选择。
- 没有候选时只回退一个相邻分类地图；仍不确定便向用户问一个能改变路线的问题。
- 一个任务确实需要多个能力时可以组合少量路线。例如“联网查资料并形成正式记忆”同时需要外部安全、领域工作和资产生命周期。
- 实例资产的 `active` 路线正常参与选择；`provisional` 只有在当前范围和条件精确匹配时作为可撤销试用参与，不能覆盖冲突的 active 资产或授权高影响动作；`candidate`、`review` 和历史正文不进入普通稳定路由。

## 最小充分上下文

路由目标不是读取最少，而是让模型得到完成任务所需的最小充分信息：

- 必须保留用户要求、实例边界、安全约束和验收标准。
- 只读取当前步骤需要的正文；进入下一阶段再读取下一份。
- 长任务可以使用本地任务包传递明确事实，不把完整聊天历史交给执行模型。
- 如果输出质量下降、遗漏关键约束或多次走错路线，应允许回溯、增加一个候选或向用户澄清，不能为了省 Token 硬做。

## 速度边界

普通明确任务应在根地图和一个分类地图后进入目标，不先扫描仓库、不建立向量库、不运行后台索引。全文检索、RAG 或向量索引只有在记忆规模和检索质量触发升级时才作为本地派生层启用。
