# 实例持续进化与母版升级兼容协定

本协定只在实例将发生正式持久变化、既有实例首次纳管、模板升级、实例迁移或相关故障修复时读取。普通启动、普通任务、既有能力的正常调用和未落盘讨论不读取全文，也不扫描实例组件、专业工作区、设备本地目录或资产正文。

它只解决一个问题：实例可以持续增加软件、Skill、模型、功能、记忆、能力、SOP 和其他资产，同时保持以后安全接收母版升级的能力。协定约束的是所有权、边界、接口、保留与回退行为，不要求每个字段、顺序、时间戳或未来扩展文字逐字相同。它不是软件商店、通用包管理器、权限审批平台、后台更新器或全量回归框架。

## 1. 不变量

1. 母版、实例、设备本地和外部依赖必须有可判定边界；升级不能用“看起来像模板”猜所有权。
2. AI Carry 发起的每次正式持久变化在写入前后都经过本协定的轻量兼容入口；兼容登记不增加一次新的用户确认，真实授权继续由当前任务、资产生命周期和安全边界决定。
3. 原生实例资产继续由自己的 Schema、地图和事务拥有；不能为了兼容再复制一份资产正文或为每条记忆建立组件清单。
4. 独立功能、适配器和本机工具依赖使用稳定组件 ID、显式路径和接口声明；不得直接修改模板核心来获得短期效果。
5. 既有实例首次接入时一次性完成活跃资源纳管。逐项处理只发生在隔离候选内部，不能在正常使用某项能力时突然搬迁、重装或切换。
6. 能兼容就保留并升级；确实不兼容就只停用相关可选组件，或只暂停依赖该必需组件的正式切换。任何失败都保留原实例、原资源和可诊断现场；一个组件、索引或登记问题不得让无关能力、对话和 Agent 主体一起停止。
7. 任何错误、自动修复、兼容迁移、重试或局部隔离都必须按 `USER_GUIDANCE.md` 用用户能理解的自然语言报告：发生了什么、影响什么、保留了什么、已经怎样处理、结果如何以及推荐下一步。确定性、可逆且属于当前已授权事务的修复不增加一轮确认，但不得静默发生。

## 2. 哪些变化必须命中

以下事件在写入前先读取本协定的共同规则；如果同时是正式资产、专业扩展、外部安装或高影响动作，再叠加其原有专门协议：

- 安装、更新、替换、停用或删除软件、Skill、模型、插件、适配器和实例模块；
- 自我学习或用户工作形成正式记忆、能力、经验、SOP、长期配置或其他持久资产；
- 新增、修改、移动或删除实例拥有的文件、接口和组件关系；
- 模板升级、完整换机、故障修复和旧实例纳管；
- 任何原本只改一个组件、实际会影响另一个组件升级行为的变化。

只读发现不会因此获得写入授权。用户或其他程序在 AI Carry 外部手工修改文件无法被实时拦截；首次纳管和升级预检必须把这种漂移作为当前事实重新分类，旧候选立即失效。

## 3. 一个入口，三种处理

### 3.1 原生实例内容

`instance/memory/**`、`instance/capabilities/**`、`instance/sops/**`、`instance/experiences/**`、正式信号、治理状态、Skill 小地图和其他已由 `core/ownership.toml` 登记的路径，继续使用现有所有者和事务。

兼容入口只核对：写集仍在合法所有权内；直接地图与引用闭合；没有越界修改模板核心；可携带、私密、本机和派生边界没有被混淆。核对通过后不创建通用组件条目。

### 3.2 专业工作区

`workspace/<extension-id>/` 继续由 `extension.toml` 和专业扩展 Schema 管理。通用协定只把它视为已经登记的专门组件类型，不复制扩展清单。未登记工作区仍原样保留并进入冲突预览。

### 3.3 独立实例组件

不能由现有资产或专业扩展表达的实例模块、能力适配器、本机工具适配器和集成适配器，登记到 `instance/components/registry.toml`，并把清单放在 `instance/components/<component-id>/component.toml`。

注册表只是小型索引；组件清单只保存所有权、接口和升级语义。正文、二进制、模型、秘密和绝对路径不得复制到注册表。

## 4. 资源层次

每个独立组件必须区分：

- `portable_paths`：随实例迁移的中立真源，必须位于该组件自己的 `instance/components/<component-id>/` 根内；
- `derived_paths`：可从真源重建的索引、报告或其他派生物；
- `device_local_paths`：当前电脑专属的绑定、运行时、模型或缓存，只允许使用 `.assistant-local/**` 相对路径；
- `private_collection_refs`：通过现有私密目录协议解析的稳定引用，不把私密正文写入组件清单；
- 外部软件实际绝对路径：只写入组件已经声明的 `.assistant-local/**` 本机绑定文件，不进入 Git、公开候选、启动上下文或完整迁移主体。

组件不得声明 `core/**`、模板入口、看板运行时或其他模板拥有路径。组件之间只能通过 `provides`／`requires` 的稳定接口标识协作，不能靠写入对方目录形成隐藏依赖。

## 5. 持久变化闭环

一次正式变化在内部完成以下最小闭环，但不把步骤逐项变成用户操作：

1. 根据当前请求和现有授权冻结允许写集；
2. 用 `core/ownership.toml`、专业扩展清单和实例组件登记为每条路径找到唯一所有者；
3. 原生内容沿原协议执行；独立组件验证自己的清单、接口和路径；模板核心直改对当前变化失败关闭；
4. 在现有动作级事务中完成写入和原协议要求的验证；
5. 回读变更后的登记、清单、路径和接口闭包；
6. 只有当前变化的语义闭包通过，才把该变化视为正式完成。无关组件的故障进入旁路诊断和局部隔离，不把当前变化伪报失败；严格发布审计仍可要求整棵候选全部规范闭合。

当前任务已经获得的安装、资产保存或其他授权可以直接作为该动作授权；本协定不重复询问。原协议要求的秘密、额外接收方、权限、公开发布、不可逆删除和高影响确认也不能被本协定绕过。

### 5.1 五级兼容结果

兼容入口不能只有“通过／抛错并停止”两种结果。它固定返回以下最高相关等级，并同时保留逐项诊断：

- `normal`：语义和规范表示都闭合，当前变化可以继续；
- `auto-repairable`：身份引用、派生计数、排序、换行、规范默认值等可由严格真源唯一确定；在当前事务中修复、回读、报告后继续；
- `migration-needed`：旧 Schema、旧字段或未知扩展需要版本适配；未知内容原样保留且不执行，在隔离候选迁移后重查；
- `component-isolated`：一个可选组件、单个索引或局部文件树不可信；只隔离该范围，其他原生资产和组件继续；
- `user-decision-needed`：所有权、必需性、覆盖、删除、隐私去向或其他实质语义无法确定；只在真正涉及正式启用、切换或不可逆动作时向用户提出一个最小决定。

规范写出仍使用当前 Schema 的固定字段和顺序；宽容读取只为兼容与修复，不把未知字段当作指令、接口、授权或可执行内容。路径逃逸、链接／重解析点、模板核心污染、所有权重叠、秘密外泄、静默覆盖用户数据和资源上限仍是硬边界，但默认只阻止当前变化或当前组件。

### 5.2 日常运行的故障边界

日常学习保存、候选晋升、跨会话信号和看板同步不能复用首次实例化、升级或发布审计的“整棵树任一点不规范就全局停止”处置。它们先验证当前动作的身份、一次性授权和当前目标，再按以下顺序处理：

1. 当前目标、正式 manifest/core、所有权或用户数据安全边界错误：拒绝当前动作，保留现场并说明最小修复入口；
2. candidate index、signal map、time map 或 startup capsule 只有可由严格真源唯一确定的身份、计数、排序、换行和规范字节漂移：在模型上下文外只尝试一次小型原子修复，严格回读后让原动作在同一次调用继续；
3. 未知字段、正文冲突或无法唯一重建：不删除、不猜改，也不消耗当前一次性选择；只暂停学习保存、晋升或信号积累这组相关能力，普通对话、只读查看和无关能力继续；
4. 与当前动作无关、拥有独立来源边界的看板项损坏：原字节和来源摘要保留，该项暂不投影，快照写入有界 `health` 告警；
5. pending control、`overflow`、`rebuild-required` 和已有事务检查点继续走各自专用恢复路线，通用修复器不得清除或改写这些合法恢复状态。

自动修复失败只能回滚一次并转为局部暂停，不能循环重试。Agent 必须在同一回复中用自然语言说明影响、数据状态、能否恢复、仍可使用范围和推荐下一步；健康成功不增加无意义报告。首次实例化、恢复、升级、发布候选和用户明确要求的完整维护仍使用严格闭包，不能用日常隔离模式冒充正式通过。

## 6. 既有实例一次性纳管

首次把旧实例接入本协定时，必须在新建隔离候选中整体完成：

1. 固定实例根、可信同版本母版、完整源树身份和回退点；
2. 只在实例根、已有地图／清单引用和当前任务明确提供的本机依赖范围内盘点，不扫描整台电脑；
3. 对照同版本母版，把每项差异分类为原生实例内容、专业扩展、独立组件、设备本地、私密、派生、模板损坏或未知；
4. 能原地登记的保持原路径和原字节。已有设备本地目录可以作为组件的合法 `device_local_paths` 登记，不为目录整齐强制重装；
5. 旧实例直接修改模板核心时，先在候选中转换为现有扩展点、独立组件、适配器或版本化迁移。无法安全转换时保留原件并报告冲突；
6. 所有活跃资源完成分类、注册表和组件清单闭合后，才把 `adoption_state` 标为 `current`；
7. 在同一个隔离候选继续执行目标版本升级、结构核对和受影响能力验证；用户真实验收前正式实例保持原样。

`current` 表示所有影响启动、升级和活跃能力的资源已经分类；它不要求删除历史归档、旧副本或用户外部软件。

## 7. 母版升级解析

升级器在现有模板升级契约内，使用旧母版基线、目标发布清单、当前实例树、实例组件注册表和被引用的组件清单形成唯一计划：

- 目标母版仍提供组件需要的全部接口：保留组件便携内容，设备本地绑定只复核、不复制、不删除；
- 发布清单提供明确迁移 ID：在隔离候选中按顺序执行，回读接口和路径闭包；
- 可选组件不兼容且没有迁移：保留全部内容并标为停用，母版其他部分可继续升级；
- 必需组件不兼容：保留全部内容并停止正式切换，明确报告缺少的接口；
- 注册表、组件清单、声明路径或当前实例在计划形成后漂移：候选过期，重新冻结和计划；这不会使正式实例停止工作；
- 身份、计数、排序、规范文本或安全默认值可由严格 manifest 和实际条目唯一确定：在隔离候选自动修复并公开报告，然后重新计划；
- 可选组件存在未登记目录、未知接口、未知字段、损坏清单或局部所有权错误：原样保留并隔离该组件；未知内容不执行，母版其他部分可以继续；
- 必需组件、身份不明内容、越界路径、所有权重叠或涉及用户数据／隐私的冲突：只暂停正式切换并给出修复或选择入口，原实例、对话和无关能力保持可用。

组件计划的源指纹只负责证明计划仍绑定同一登记和声明内容；平台完整树、普通字节、重解析点、备用数据流和权限等完整身份仍由 `UPGRADE-CONTRACT.md` 负责。

## 8. 可插拔边界

组件声明 `activation`：`immediate`、`next-session`、`restart-required` 或 `migration-required`。只有真实支持立即切换的组件才能使用 `immediate`；驱动、数据 Schema、长期服务或安全边界不能假装热插拔。

解耦目标是稳定所有权和接口，不是把每个文件拆成插件。一个清楚的模块可以内部保持内聚；跨模块直接写文件、硬编码本机绝对路径和依赖未登记副作用才是需要消除的耦合。

## 9. 验证重量

每次普通实例变化只做：当前写集所有权、命中的清单／引用、接口闭包和该能力的最小真实检查。它不触发全产品回归，也不因一个未命中组件的格式或健康问题扫描、迁移或停止全部能力；若按需检查顺带发现问题，只生成有界诊断并报告。

首次纳管和母版升级额外做：实例保留路径的完整结构与字节核对、源漂移检查、必要迁移、受影响能力检查、回退和第二次执行零变化。只有本协定、升级解析器、共享核心接口、安全边界或正式发布变化时，才运行更广的产品门禁。

## 10. 公开与私密边界

公开空白模板包含本协议、Schema、空注册表和空组件模板，但不预装任何真实组件、本机绑定、软件路径、维护者习惯或实例专业内容。`.assistant-local/**`、真实 `.assistant-private/**`、`AGENTS.override.md` 和 `maintainer-private/**` 继续排除。

私密 Dev 可以保存维护者已经核实的开发经验和失败修正；普遍适用的兼容结论必须去身份化后进入本通用协议，不能复制真实实例正文。

## 11. 完成定义

只有以下条件同时成立，才能宣称实例已经受本协定保护：

- 严格发布审计中的注册表身份、计数、排序和所有清单引用通过规范解析；日常操作入口已把可修复表示漂移收口，并把未解决问题限制在明确组件范围；
- 所有活跃的非原生组件都已登记，没有未解决的活跃未知目录；
- 原生资产、专业扩展和独立组件的所有权互不重叠；
- 所有必需接口在当前母版或已登记组件中可解析；
- 设备本地和外部绑定没有进入便携或公开范围；
- 直接模板核心修改已经转换或作为明确冲突保留；
- 隔离候选保留核对、相关能力验证、回退和幂等检查通过；
- 正式实例已经完成用户真实验收。

本协定保证“兼容时升级，可修时修复，不兼容时局部隔离且可解释”，不能保证任意外部软件、任意手工核心修改和任意未来接口天然兼容，也不承诺用宽容读取掩盖损坏的正式发布物。
