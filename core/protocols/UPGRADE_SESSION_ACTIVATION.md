# 升级后的宿主会话激活

本协议只在两种情况读取：Agent Carry 产品文件在当前会话中完成切换，或用户在新会话中要求继续完成升级验收。它补齐“文件已经安装”和“当前运行中的 Agent 已采用新版行为”之间的空白，不改变实例资产、组件或升级文件事务。

## 1. 五个阶段不能混成一个“完成”

升级依次区分：

1. `source-verified`：目标来源、标签、Release、发布清单与解压树已经核对；
2. `files-installed`：隔离候选中的目标产品文件和实例保留内容已经验证；
3. `instance-switched`：稳定入口已经切到验证后的目标目录，胶囊与双快照有效；
4. `session-activated`：当前宿主会话确实从目标版本启动，或宿主提供了可验证的指令链重建能力并已经执行；
5. `behavior-accepted`：目标版本声明改变的至少一项真实行为已经在激活后的会话中出现。

只有前五项都成立，才可以对用户说“升级完整完成”。文件版本、哈希、启动胶囊、快照、静态字符串或在旧会话中手工重新打开新版 `AGENTS.md`／`BOOTSTRAP.md`，只能证明磁盘内容，不证明宿主已经重建本次运行的指令链。

## 2. 当前会话的保守判断

升级开始时，保留本次启动入口实际返回的产品版本作为会话基线。目标文件切换后：

- 会话基线早于目标版本时，默认状态是 `session-activation-required`；
- 会话基线未知时，同样不能宣称已激活；
- 只有宿主明确支持、实际执行并能验证一次指令链重建时，才允许在同一会话重新运行启动入口并继续行为验收；
- 普通文件重读、上下文摘要、模型自称“已经理解新版”或静态校验通过，不属于可验证重建。

当前宿主不能可靠热重载时，不把它当成升级失败，也不回滚已经验证通过的目标实例。文件保持已安装，升级状态停在“等待新会话激活”；旧会话仍可进行不依赖新版语义的说明、只读检查和其他独立工作，但不得用目标版本的新行为作完成承诺。

## 3. 新会话的轻量续接

旧会话向用户提供一个明确、可直接执行的新任务动作，不要求用户运行终端或重新升级：在同一 Agent Carry 根目录开启新任务，并说明“继续完成升级后的会话激活验收”。若宿主能够直接创建一个真正的新运行，可以替用户完成；不能时如实请用户新开任务，不能伪装已经重启。

新会话按以下顺序完成：

1. 正常执行 `BOOTSTRAP.md` 和固定启动入口，取得本次会话起始版本、实例 ID 与 manifest 摘要；
2. 进入 `HOST_SESSION_RESUME.md`，把升级前会话的接入回执视为旧版本回执，只恢复一个匹配档案；
3. 核对实例 ID、目标版本、启动胶囊、稳定入口和未完成的升级激活目标，不重复文件升级，不修改用户资产；
4. 从目标发布说明中选择一项真正改变的行为做最小验收。行为型补丁必须观察真实行为，不能只搜到规则文字；纯文件或内部修复若发布说明明确没有行为变化，可用一次目标启动／路线结果代替；
5. 返回新的会话接入回执，并分别报告文件安装、会话激活和行为验收结果。通过后才写 `behavior-accepted`。

新任务可使用下面这段自然语言，不要求固定字段或精确内部 ID：

> 请在当前 Agent Carry 根目录继续完成升级后的会话激活验收。先按 BOOTSTRAP 正常启动并走轻量会话恢复，核对当前实例与目标版本；不要重做文件升级或修改用户资产。再从目标版本的正式说明里选一项真实变化做最小验收，分别告诉我文件是否已安装、当前新会话是否已采用新版、行为是否通过。

## 4. 行为验收必须真实但保持轻量

行为验收只选一个最能代表本次变化的场景。需要某项长期资产、错误或用户选择才能触发的行为，不得伪造前提：有真实条件就实际触发；没有时明确说明尚不能验证，并保持待验收。一次回复外观、一个 emoji 或一句口头承诺本身都不是充分证据，除非它正是发布说明要求且前置条件真实成立。

不为每个宿主、每个字段、每个资产建立矩阵。发布前只保留少量高信息量场景：旧会话不能误报完成；新会话可以闭合；宿主若有真实重载能力可以闭合；行为失败只暂停激活；磁盘启动真源无效才回滚。

## 5. 失败范围与用户报告

- 来源、目标树、实例切换、启动胶囊或正式快照无效：这是文件升级失败，按升级事务恢复旧实例。
- 文件与实例切换有效，但当前会话未激活：保留新实例，不回滚；只把升级完成结论保持为待激活。
- 新会话已加载目标版本，但代表行为未通过：保留实例与证据，只隔离目标版本完成结论；普通对话、只读能力和不依赖该行为的功能继续可用。
- 无论进入等待、新会话续接、重试、行为失败或回滚，都用自然语言说明发生了什么、影响范围、数据是否安全、仍可用什么和推荐下一步。

完成状态不得靠降低校验、假造行为、反复重启、删除失败现场或把“我重新读过文件”改写成宿主热加载来获得。
