# 模型等级不足时的延期任务

本文件只在新增、查看、恢复或删除延期任务时读取。普通任务不读取延期正文。

延期卡从 `core/templates/deferred/blank-deferred-work.md` 创建并保存到 `instance/deferred/`。它应保存：稳定 ID、任务摘要、需要的等级、延期原因、恢复路线、必要本地证据引用、创建时间、带时区的提醒时间、暂停时间、触发修订和当前状态。不得保存凭据、自动恢复外部动作的令牌或不必要的完整上下文。

流程：

1. Agent 提示需要切换模型，并等待用户确认。
2. 用户不能切换时，Agent 询问是否延期；同意后再询问或确认提醒时间，写卡并继续其他工作。用户不需要提醒时可以保留无日期卡，只在明确查看延期任务时出现。
3. 有提醒时间时，把卡片元数据投影到 `instance/maps/time-trigger-map.toml`，再把所有时间项的最早有效时间和总数聚合进唤醒胶囊。日期未到时普通启动不读取时间索引或延期卡。
4. 到期时只读取时间索引并注入固定长度提醒，例如“有 2 项 Level 3 任务到期，是否查看？”；具体任务不进入上下文。
5. 用户明确选择某项后才读取对应卡和恢复引用；用户推迟时写 `snoozed_until`，不改写原始提醒时间。
6. 用户确认已切换模型后，按卡中的恢复路线继续；完成或拒绝后删除卡或按用户需要保留最小历史，并同步移出时间索引、重算最早唤醒时间。

所有写入使用统一触发事务。AI Carry 关闭期间不会后台计时；到期表示第一次不早于提醒时间的活跃启动或检查点会发现它。
