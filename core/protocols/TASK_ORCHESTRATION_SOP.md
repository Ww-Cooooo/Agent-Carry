# 跨 Agent 任务协作 SOP

本 SOP 只在用户选择跨 Agent／跨宿主执行，或当前任务确实需要把一个边界清楚的子任务交给另一个 Agent 时读取。普通任务、同一 Agent 内的连续工作和简单验证不创建任务包。

## 先判断是否需要交接

- 当前 Agent 能在现有上下文和授权内完成时，直接完成，不为了流程拆任务。
- 需要独立执行环境、用户明确要求另一个 Agent、或一个子任务可以安全并行时，才交接。
- 产品身份、公开／私密边界、用户数据处置、不可逆动作和跨组件取舍不能只靠一句“交给更强模型”；必须由持有完整事实的一方明确决定或交还用户。
- 模型等级只表示任务复杂度建议，不把经济型模型当成无思考执行器，也不因无法证明模型名阻断边界清楚的工作。

## 最小任务包

同一 Agent 内不建包。跨 Agent 时默认只创建一个 `TASK.md`，放在 `.assistant-local/task-handoffs/<task-id>/`，包含：

- 背景与父目标；
- 允许读取／修改的准确范围和禁止范围；
- 已经确定的决定与仍可自由判断的空间；
- 可观察的完成条件；
- 必要的来源、隐私、外发和本机运行边界；
- 完成或失败后应回传什么。

只有结果无法在回复中清楚返回、需要跨会话保存，或用户明确要求文件证据时，才再写一个 `RESULT.md`。不要固定生成九份说明、变化、证据、日志和安全文件；复杂任务确实需要时可以在 `TASK.md` 中增加小节，而不是先制造目录仪式。

如果执行方尚未接入当前 AI Carry，在 `TASK.md` 中加入最小手动接入说明和任务胶囊；已经接入时只传任务胶囊。不得假定另一个 Agent 自动看见原聊天、私密资产或本机绑定。

## 执行边界

- 执行方只读取完成任务所需的地图、文件和工具，不加载整个聊天或全部资产。
- 可以在授权范围内选择实现细节和进行少量有根据的自我修正；范围、所有权、外发对象或不可逆影响变化时交还决定。
- 对复制实例中会启动本机软件的组件，先核对副本绑定不会回指真实实例；失败只暂停该组件。纯文档和不启动本机工具的任务不增加这一步。
- 一个子任务失败只影响该子任务；返回错误、已尝试修正、保留内容和推荐下一步，不让父任务其他能力一起停止。
- 不用大量截图或完整日志代替结论。证据只需足够让父任务验证关键主张。

## 返回、复核与学习

执行方返回：状态、实际结果、变更范围、关键证据、未完成项和推荐下一步。父任务先验证最重要的产物或行为，不把一句“已通过”当作证据，也不机械重跑整个产品回归。

交接暴露出的可复用经验按资产生命周期处理；学习回执简短告诉用户学到了什么、是否形成候选或正式资产。任务结束仍以用户总体目标的真实 `👉 接下来` 收尾。

临时任务包默认不进入正式记忆和公开仓库。任务完成且用户不再需要追查时可以按授权清理；失败现场和用户要求保留的证据不能自行删除。
