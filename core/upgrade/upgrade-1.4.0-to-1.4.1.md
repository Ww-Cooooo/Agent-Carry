# 1.4.0 → 1.4.1 首次实例化闭包补丁说明

这是一份 1.4.1 的正式补丁迁移说明，但文件名或版本号本身不是升级授权。只有官方固定 `v1.4.1` 标签、对应 Release 对象、`release-manifest-1.4.1.toml` 和源码 ZIP 解压后的完整树一致，并且用户明确选择升级这个固定版本时，才能在隔离候选中执行。该 authority 只适用于这一次实例升级，不授权未来的提交、推送、标签、Release 或 Pages。

## 修复什么

1.4.0 的空模板可以启动，旧实例也可以通过 1.3.1 → 1.4.0 升级，但首次创建指南曾把几份身份文件漏在原子写入事务之外，或对空候选索引时间给出互相矛盾的要求。严格按旧指南创建新实例时，manifest 已变成新身份而验证索引、组件登记表或启动胶囊仍可能停在模板态，随后快照生成会正确拒绝这套半实例状态。

1.4.1 不放宽任何严格加载器。它把 manifest、档案、身份地图、信号、候选索引、结果验证索引、组件登记表、宿主登记、Skill 状态、治理排期、启动胶囊和双快照放进同一个可恢复首次实例化事务，并要求写后回读、故障回滚和第二次执行零变化。

## 日常容错和正式升级是两条不同路线

1.4.1 同时修复了“一个无关坏项拖住整个实例”的运行问题，但这不会放宽本页的升级闭包。首次创建、升级、发布和维护审计继续使用 strict：任何被隔离的坏来源都不能混进正式候选。普通学习保存、晋升和跨会话信号才显式使用 operational；它们可以保留无关坏项的原字节并只隔离那一项，当前目标、身份、核心清单、路径逃逸、链接／重解析点和私密边界仍会停止当前动作。

有效 manifest 可以唯一重建的启动胶囊，以及能从现有正式候选／信号来源唯一闭合的派生索引，最多自动修复一次：先在隔离阶段构建，原子替换，严格回读，再重试原动作。它不会猜测新时间、revision、业务条目、验证证据或删除未知字段；无法唯一闭合时只暂停相关学习／信号能力。每次错误、局部暂停和自修复都要向用户说明影响、数据状态、恢复可能、仍可使用的能力和推荐下一步。

## 先区分两种 1.4.0 来源

### 尚未实例化的空模板

- 在尚不存在的隔离目录中组装固定 1.4.1 空模板，不在原目录上覆盖；
- 保持 `instance_id=template`、`state=template`、空档案、空验证记录、空候选、空组件和三张未排期治理卡；
- 使用目标 1.4.1 的严格启动胶囊和空态双快照，先证明仍是干净模板；
- 再从该隔离副本运行通用与剪辑领域两条首次创建 smoke。测试只使用虚构信息，不把场景内容预装进正式模板。

### 已经实例化的助手

- 冻结完整 1.4.0 源树和回退点，原实例保持不动；
- 保留实例 ID、锁定方向、档案、交流方式、学习政策、地图、信号、治理排期、宿主记录、Skill 状态、记忆、能力、SOP、经验、候选、真实验证记录、专业扩展、独立组件、工作区、本机绑定和私密引用；
- 只把实例清单中的产品版本从 1.4.0 更新为 1.4.1；`created_from` 和其他用户拥有字段保持原值；
- 不重新执行首次实例化，不把第一项任务、历史主张或测试结果写成验证记录、候选、资产或组件；
- 空或非空结果验证索引继续绑定原实例身份；候选索引只有业务投影真实变化时才更新时间，本补丁本身不刷新；
- 组件登记表和组件正文原样保留。未知、损坏、越界或未登记内容继续保留并停止完整兼容结论，不用空注册表覆盖；
- 组件清单里符合 Schema 的结构化 `private_collection_refs` 可以进入完整真源摘要，但不会进入看板投影；绝对私密路径、绝对设备本地路径或非法 locator 继续失败关闭，不能为了生成快照删掉已有合法引用；
- 从合并后的真实实例清单重建严格启动胶囊，从合并后的真实实例内容重建 public/dist 两份逐字节一致快照。

## 完成门

升级只在以下结果全部成立时完成：来源树不变；候选的模板拥有文件来自固定 1.4.1；全部实例拥有路径逐路径、逐字节保留；胶囊摘要和实例身份闭合；两份快照逐字节一致；1.4.1 空模板能完成两条首次创建链；代表性中途失败恢复完整 1.4.0；对同一候选第二次执行不产生文件、记录、时间或快照差异；strict 仍拒绝 operational 隔离的坏来源；日常容错只影响无关项且保留其原始字节。

任何失败都保留原 1.4.0 和隔离现场并停止。不得修改真实实例来“帮测试通过”，不得删除冲突、降低快照或身份校验、改权限、执行实例登记的软件，也不得把本机或私密内容复制进公开包。
