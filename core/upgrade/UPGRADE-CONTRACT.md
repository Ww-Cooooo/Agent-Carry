# 模板升级机器契约

默认官方更新来源由 `core/upgrade/official-source.toml` 唯一登记。升级输入可以来自该公开仓库正式 Release 标签对应的 GitHub 自动生成源码 ZIP，也可以来自用户指定的本地离线升级包；两者使用同一种发布清单。用户明确指定其他仓库、附件或镜像时，将其标为非官方来源并在读取或下载前取得选择，不从搜索结果自行替换官方源。

1. 只有用户明确提出检查更新时，才读取官方来源并访问网络；不得后台检查、自动下载或强制升级。公开来源不要求用户登录 GitHub。
2. 解析当前实例清单，并从当前实例的官方来源记录取得来源地址与核验规则；目标发布清单必须从这次取得或由用户唯一指定的目标包中读取。旧实例自身 `core/upgrade/` 目录只证明它安装时包含哪些历史文件，枚举其中最高文件名不得用来断言“没有新版”。
3. 验证来源身份、正式 Release 状态、轻量标签目标、公开 `main` 与最新正式标签的一致性、清单结构、目标版本、解压后的文件集合、逐文件摘要和路径安全。默认先使用目标标签对应的版本化 ZIP；只有公开 `main` 已证明指向同一标签提交时，才允许使用“最新版 ZIP”。用户已经唯一提供本地包或解压树时，按同一规则核验后直接作为目标，不得退回旧实例历史目录自行推断版本；无法联网且没有唯一目标时才请求本地包。GitHub 可能重新生成压缩容器，因此外层 ZIP 的大小和 SHA-256 只作本次传输记录，不能替代解压内容身份；离线包仍按不可信输入检查，无法闭合官方身份时只可检查而不能替换正式实例。目标版本要求随包升级器时，该升级器必须现场核对登记仓库的正式 Release、固定标签提交、目标 Git 树、目标逐文件字节和发布清单；调用者手写记录与目标包自报字段都不能单独证明官方来源。
源目录即使已经自报目标版本，也不能只凭版本字符串返回“已是当前版本”。在用户明确检查官方更新的同一次动作中，仍须现场闭合正式 Release、固定标签目标整树和发布边界，再核对本地核心、启动胶囊、快照和静态产品路径；本地候选、混合树或损坏树只暂停这次更新检查，不能冒充官方当前版。

4. 按 `core/ownership.toml` 与目标发布清单的 `[classification].precedence` 分类现有内容；机器消费者必须先执行适用的版本化迁移，再按优先级为每条路径得到唯一动作，不能把重叠 Glob 同时当成替换和保留。实例目录中清单明确列入 `replace_instance_guides` 的固定 `README.md` 原则上属于目标模板说明；但替换前必须先检查实例清单和地图是否把其中某一份作为用户正文引用。若存在实时引用，先执行目标发布清单的版本化迁移：逐字节复制到用户拥有路径、核对摘要、更新引用并回读成功，之后才能把原路径替换为目标说明。目标路径已有不同内容、引用语义不明或摘要不一致时停止并显示冲突，不能覆盖或猜测合并。`replace_instance_guides` 只赢得列明的精确 `README.md`；同目录的其他文件、用户新增子目录、迁移后的档案和本地私密层即使匹配宽泛 `preserve` 规则，也不得因名称相似被替换。`.assistant-private/catalog.toml`、`bindings.toml` 和正文都属于实例本地状态：目标模板不得创建、覆盖、清空或把旧设备绝对路径写进公开文件。`workspace/<extension-id>/extension.toml` 存在且通过 Schema 时，按清单分别保留便携正文、重建派生物、排除设备本地层并连接私密集合；没有工作区的实例保持零变化。存在 `workspace/**` 但缺少合法清单时标为未登记扩展冲突，原样保留并停止“完整兼容升级”结论，不递归猜测所有权、执行脚本或删除内容。存在 `instance/components/registry.toml` 时只按注册表定向读取清单，核对组件便携、派生、设备本地和私密边界以及 `provides`／`requires` 接口闭包；身份、计数、排序、换行和安全默认值等可唯一推导差异先在隔离候选自动修复、回读并自然语言报告。可选组件未登记、清单损坏或接口不兼容时原样保留并局部隔离，母版其余部分继续；必需性不明、必需组件、越界或所有权冲突只暂停正式切换，原实例和 Agent 继续可用。旧实例没有注册表时，先在隔离候选执行一次性完整纳管，不能把未知内容延后到日常使用时突然迁移。
5. 生成预览，不写文件：列出当前版本、目标版本、来源、替换、迁移、保留、删除、冲突、不兼容扩展和实例组件动作。组件动作只使用保留、迁移、重新核验本机绑定、停用并保留或停止并保留；不能在预览或普通能力使用中执行安装器。
6. 用户选择保留现状或迁移升级。
7. 迁移升级先确认当前系统中一个稳定、用户可见的看板入口已经存在，或在用户授权下先创建／修复它；入口目标必须是当前正式实例根 `dashboard.html`，工作目录是实例根，参数为空。入口不存在时不能先切换目录再用“缺入口”否定一个内容正确的新实例；也不能未经用户授权静默创建入口。随后创建本地临时回滚副本，并在同一文件系统的临时目录组装新核心和保留资产。目标模板文件必须来自已经固定身份的发布内容清单或可信目标提交的允许集合；发布清单中的 `**` 是选择约束，不是对开发工作树做无边界递归复制的命令。`.git`、`node_modules`、缓存、临时构建目录和维护者私密层即使位于匹配目录下也不得进入候选。先执行发布清单中的 `migration_rules`，再放入目标模板核心和精确目录说明，最后恢复或迁移个人资产；逐路径证明除说明与有依据的 Schema 迁移外，用户资产和实例档案没有被覆盖。对旧版把 `instance/profile/README.md` 作为 `profile.user_preferences_ref` 的实例，先把该文件逐字节迁移到 `instance/profile/approved-profile.md`，核对摘要并更新引用，再替换目录说明。把所有 `asset_kind="task-family"` 路线的 `state` 规范为 `on-demand`，其他字段不借机改写。私密目录只在登记、命中引用、隐私导入导出或完整迁移事件中从当前相关引用渐进建立；普通升级不得枚举整个 `.assistant-private/assets/`、外部绑定根、全部扩展或所有资产正文。检查实例方向锁、实例展示名、交流方式兼容、学习政策、资产风险／授权／成熟度兼容、地图目标、长期治理卡、跨会话控制修订、触发注册表、唤醒胶囊、非启动时间索引、宿主接入协议／Schema、私密目录按需入口、看板动作/快照与扩展接口。正式动态状态、延期卡、不含秘密的宿主档案、私密目录、绑定和正文全部保留；长期治理卡按稳定 ID 迁移实例状态。两个信号派生投影从合并后的状态元数据重建；旧字段只在相关内容被使用、修改、导出或复核时渐进补齐，不为补字段扫描宿主、日志、私密目录、扩展正文或资产正文。

   当目标版本引入严格启动胶囊、正式资产确认门或结果验证证据索引时，这三项必须出现在目标发布清单的迁移分类和规则中。实例 manifest、方向、指导方式、学习政策、语言、档案引用、`instance/startup-capsule.toml` 和派生快照构成同一次可恢复写集：严格 manifest 先在模型上下文外校验，再生成胶囊并核对源摘要；任一环节失败则恢复整组旧状态。旧正式资产缺 `confirmation` 时，只能按风险做确定性保守兼容并同步修改 frontmatter 与直接路线；未知值单项失败关闭。旧 `policy-authorized`、单独 `approved_by_user=true` 或其他策略推导字段不能证明用户已批准。旧成熟度、成功次数或跨宿主声明只有在现有真实记录能于 `instance/validations/index.toml` 闭合时才保留；证据不足进入 `needs-evidence`／`review`，不得补造验证 ID、时间、任务或批准记录。
8. 复制和切换必须服从动作级事务。写入前按发布清单冻结唯一相对写集，并逐路径记录源存在状态、普通文件字节摘要和候选摘要；发布清单没有明确删除项时，源独有路径一律留在原位，不得用整树差异推断 removal。文件存在但损坏时保留原字节并停止，不能按“缺失”创建空默认值。深路径使用同目录短临时名，不把长时间戳后缀附加到每个深层文件。Windows 上每个触碰路径及其祖先必须拒绝链接、重解析点、非普通文件和大小写／Unicode 规范化碰撞；不触碰的工作区、本机层、私密层和未知根文件不得为了“完整树证明”而遍历、复制或读取正文。不能只用文件数宣称完整复制，也不能把未检查的元数据说成已保留；本契约只对明确触碰路径作恢复承诺。
在隔离候选复制完成、叠加任何实例内容之前，必须把复制结果与本次现场核验的目标整树指纹再次比较；不一致只暂停本次升级。每个同目录暂存文件必须先登记进恢复状态再复制和校验，名称包含本次编号；普通异常会清理本次暂存，强制中断遗留的旧编号暂存也不能阻塞新编号重试。Windows 触碰文件若是硬链接，替换普通文件会拆掉链接拓扑，因此必须在切换前局部待复核；硬链接或命名数据流枚举本身失败也不能静默当作不存在。只读 `prepare`／`confirm` 实际访问官方来源时，回执必须如实报告使用了网络。

9. Windows 权限复制先检查源对象是否具有受保护 DACL、显式访问规则或必须保留的非默认所有者。普通同父目录候选优先让权限自然继承；只有检查表明语义确实依赖显式 DACL 时才复制普通访问规则。不得默认复制 SACL／审核规则或所有者，不得因权限复制失败自动提权、修改系统策略或把工具退出码 0 当成成功；同时解析工具输出并回读目标权限。权限无法等价保留时在目录切换前停止，保留原实例和空／失败现场供诊断。
10. 完成合并后，必须从**合并后的真实实例真源**重新生成 `dashboard/public/snapshot.js` 和 `dashboard/dist/snapshot.js`；目标模板自带空态快照只可作为组装中间物，不能成为实例最终快照。两份结果必须字节一致、身份／版本／实例名／资产／待办与正式来源一致；第二次重建不得继续变化。生成失败时保留旧实例或回滚，不能显示模板空态后声称升级成功。
11. 目录切换以同一动作级事务完成；失败时恢复所有实际触碰路径。宿主正在把实例根作为工作目录、Windows 因此不能重命名整个根时，不得要求用户关掉整个 Agent 或把 `EBUSY` 当成无法升级：先验证隔离候选，再保持根路径不变，只事务替换发布清单拥有且候选字节实际不同的文件；每个旧文件先进入带操作清单的有界回滚包，新建文件也必须记录“原先不存在”。任何失败按已完成操作逆序恢复并逐路径回读。成功后只清理成功候选，变化文件回滚包继续保留；清理失败只报告残留，不回滚有效实例。保留的失败现场占用一个带编号尝试，新重试使用下一个编号，不删除旧现场也不永久阻塞。切换后组合验收本地 `file://` 看板：回读快捷方式目标、工作目录和参数；核对根入口、最终离线资源和快照身份胶囊；从入口实际启动并确认浏览器没有文件缺失／错误页且打开了新页面；再运行与本次风险相关的快照、离线资源和实例测试。能精确读取地址栏时进一步核对最终 `dashboard/dist/index.html` 和参数；控制工具无法读取地址栏本身只是证据能力限制，若其他独立证据已经一致，不得仅因此回滚有效实例。真实入口缺失、目标不符、错误页、身份不符或测试失败仍必须失败关闭并恢复触碰路径。
12. 在替换前后分别运行确定性语义检查：所有地图目标存在；正式 `active`、`provisional`、`review` 记忆／能力／SOP／经验有类型一致的直接路线；每项可用正式资产都能证明用户明确确认或可核验的既有明确批准，风险策略只影响候选顺序；frontmatter 与路线的确认门一致且来自正式注册表；能力、SOP 和宿主执行经验的成熟度声明能在按需验证证据索引中闭合；缺证据的旧声明只进入 `needs-evidence`／`review`；`task-family` 全部为 `on-demand` 且不计资产；实例状态下没有用户档案继续引用将被替换的目录说明；实例组件注册表身份、计数、排序、清单路径、所有权和接口闭包一致，设备本地路径不进入迁移主体，未登记组件不被静默认领；已登记扩展按清单分类且未登记工作区不被静默认领；私密目录／绑定／正文逐字节保留，私密目录 Schema、迁移 Schema、实例组件 Schema 和可选扩展 Schema 路线存在但普通启动不读取；严格启动胶囊与当前 manifest 摘要、实例身份、版本、方向、语言和引用一致，普通启动不读取原始 manifest 展示文字、组件注册表、验证索引或资产正文。第二次对同一候选执行迁移不得继续产生差异。
13. 文件事务与入口验收通过后，按 `core/protocols/UPGRADE_SESSION_ACTIVATION.md` 单独判定当前对话采用状态。机器状态继续区分现场官方来源核验、目标替换边界、`files-installed`、`instance-switched`、`session-activation-required`／`session-activated` 和 `behavior-accepted`；只有宿主真实事实闭合后两项时，才可以输出升级完整完成。本次运行的启动版本早于目标版本时，普通重读目标文件不构成采用证据。目标升级器返回 `sessionReentryCommand` 时，只执行同次 `confirm` 返回的精确命令；本地命令只能核对同次事务引用、变化文件回滚包、manifest 摘要、严格胶囊、双快照和目标代表路线是否存在，必须返回 `target-runtime-validated` 并保持会话与行为待接续。它不得自行签发 `sessionActivated=true`、`behaviorAccepted=true` 或把无密钥摘要叫作宿主权威回执。Agent 随后按协议在安全节点真实重载最小产品规则并执行一项无破坏代表行为；能观察这些事实的宿主可以闭合后两项，不能观察时保持待接续。会话待接续或行为验收失败保留有效新实例、用户数据、当前对话和证据，`rollback_required=false`，无关能力继续；切换后的文件版本、启动胶囊或真源无效才进入文件事务回滚。宿主无法证明原地接续时，报告文件升级与当前对话采用状态，并说明下一次自然打开采用新版；不要求用户重做升级或专门新建验收任务。
14. Agent 自动完成能够真实执行的文件、当前对话采用和行为验收并向用户报告；不能观察的宿主事实保持待接续，不伪造完成。用户确认结果和结束回退保护后，才删除由本次升级创建且不属于失败证据的成功候选或变化文件回滚包。用户自己的备份、失败现场和明确要求保留的证据不自动删除。

若核心被用户自定义，先按实例持续进化兼容协定在隔离候选判断能否转换为已有扩展点、独立组件、适配器或版本化迁移；能转换并验证时继续升级。仍无法安全表达时不做逐行猜测合并，保留原实例并转为“新模板实例 + 迁移已确认个人资产／组件”的明确冲突路线。
