# 模板升级机器契约

升级输入可以来自用户指定的模板仓库路径，也可以来自离线升级包。两者使用同一种发布清单。

1. 解析当前实例清单和目标发布清单。
2. 验证清单结构、目标版本、文件摘要和路径安全；离线包无需访问 GitHub。
3. 按 `core/ownership.toml` 分类现有内容。
4. 生成预览，不写文件：将替换、迁移、保留、删除、冲突和不兼容扩展。
5. 用户选择保留现状或迁移升级。
6. 迁移升级先创建本地临时回滚副本，再在临时目录组装新核心和保留资产；检查实例方向锁、交流方式兼容、学习政策、资产风险／授权／成熟度兼容、地图目标、长期治理卡、跨会话控制修订、触发注册表、唤醒胶囊、非启动时间索引、宿主接入协议／Schema、看板动作/快照与扩展接口。旧实例缺少 `profile.guidance_mode` 时按 `balanced` 读取，补字段不得改变锁定方向。正式动态状态、延期卡和不含秘密的宿主档案保留；长期治理卡按稳定 ID 使用目标模板正文并迁移实例的启停、锚点、完成、到期、延后和触发修订字段，ID 缺失、重复或语义冲突时停止自动合并。两个信号派生投影从合并后的状态元数据重建；旧资产的新字段只在相关资产被使用、修改或复核时渐进补齐，宿主能力在下次相关使用时重新验证。旧宿主档案缺少“模型选择／实际路由／辅助模型／自动上下文”字段时按 `unknown` 保持可读，不为补字段扫描宿主、日志或记忆正文。
7. 原子替换目标文件；失败时恢复回滚副本。
8. 用户验收后删除临时回滚副本。

若核心被用户自定义且无法安全套用清单，默认不做逐行自动合并；转为“新模板实例 + 迁移个人资产”。
