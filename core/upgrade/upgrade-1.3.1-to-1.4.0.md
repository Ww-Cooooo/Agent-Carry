# 1.3.1 → 1.4.0 实例兼容升级说明

这是一份 1.4.0 的正式迁移规则说明，但文件或版本号本身不是升级授权。只有官方固定 `v1.4.0` 标签、对应 Release 对象、发布清单和源码 ZIP 解压后的完整树相互一致，并且用户明确选择升级这个固定版本时，才执行下面的流程。该 authority 只适用于这一次实例升级，不授权未来的提交、推送、标签、Release 或 Pages。

## 这次升级解决什么

1.3.1 已经能保留原生记忆、能力、SOP、经验、Skill 小地图、专业工作区和本机私密层，但没有一个统一的小协议说明“实例后来安装的软件、模型、适配器和独立功能归谁拥有，以及母版升级时怎么处理”。1.4.0 增加一个按需兼容入口和空组件注册表：原生资产与专业扩展不重复登记；只有独立模块和适配器才有组件清单。

它不引入软件商店、后台扫描、自动安装、第二套审批或每次任务都跑的全量回归。普通使用和普通启动不读取组件注册表。

## 升级前预览

升级器先验证固定 1.3.1 来源、固定 1.4.0 正式目标、完整源树身份和回退点，再在尚不存在的隔离目录创建候选。正式实例保持不动。

如果旧实例还没有 `instance/components/registry.toml`，预览显示“一次性纳管”；如果已经有合法且 `adoption_state=current` 的注册表，只重新核对登记、来源指纹和接口，不重复改造。

盘点范围只包含实例根、已有地图／清单引用，以及当前升级明确给出的本机依赖路径。不扫描整台电脑，不执行旧脚本、安装器或二进制。

## 一次性纳管

在隔离候选中把与干净 1.3.1 母版的差异分类：

- 原生记忆、能力、SOP、经验、Skill、信号、治理、验证记录和实例地图继续由原结构拥有；
- 有合法 `extension.toml` 的专业工作区继续由专业扩展拥有；
- 独立模块、能力适配器、本机工具适配器和集成适配器建立一个稳定组件 ID、一个组件清单和一条注册表记录；
- 当前电脑的软件、模型和缓存保持原位，只登记 `.assistant-local/**` 边界；根外绝对路径只存在对应的本机绑定文件；
- 私密正文继续由私密目录协议拥有，组件只保存稳定 `private://` 引用；
- 直接修改母版核心的旧功能只在候选中尝试转换为现有扩展点、组件、适配器或明确版本迁移；
- 无法安全归类的内容原字节保留并成为冲突，不删除、不猜测、不用空模板覆盖。

只有所有活跃、会影响升级的内容都有唯一所有者，组件接口闭合，保留路径核对和受影响能力检查通过后，才把 `adoption_state` 写为 `current`。整个纳管在本次升级候选内一次完成，不会等到某项能力正在使用时突然搬迁或重装。

## 组件升级动作

升级器只定向读取注册表引用的组件清单：

- 目标母版仍提供所需接口：保留组件；本机绑定只重新核验；
- 目标发布清单逐字声明适用迁移 ID：只在候选中执行该迁移，然后重新解析；
- 可选组件仍不兼容：保留全部内容并停用该组件，母版其他部分可以继续；
- 必需组件仍不兼容：保留全部内容和旧实例，停止正式切换并说明缺少哪个接口；
- 注册表、清单、便携内容、派生内容或本机绑定在计划后变化：旧计划作废，重新冻结和预览。

接口相容只说明结构可连接，不能冒充软件已经安装、模型可用或真实任务已经成功。相关能力仍做自己的最小健康检查。

## 保留与排除

逐字节保留实例身份、方向、交流方式、学习政策、原生资产、候选、验证记录、专业扩展、已登记组件、私密状态和当前电脑上的本机绑定。`instance/components/README.md` 是模板目录说明，可以替换；注册表需要身份迁移；组件正文不由母版覆盖。

公开空白模板只包含兼容协议、Schema、空注册表、空组件清单模板、严格解析器和验证器。真实组件、本机路径、软件、模型、秘密、维护者习惯、私密 Dev 资产和专业工作区都不得进入公开候选。

## 验证、回滚与完成

候选必须通过：严格解析；唯一所有权；接口闭包；未知内容失败关闭；来源漂移失效；便携路径逐字节保留；本机绑定不迁移；启动胶囊摘要；两份真实快照；受影响能力最小检查；完整树身份；回滚；以及第二次执行零变化。

任何失败都保留旧实例、候选和诊断现场，不通过删除冲突、降低校验、重装已有软件或把可选组件假装兼容来继续。只有固定正式版本具备发布 authority、全部检查通过、完成目录切换并经过用户真实验收后，才能宣布升级完成。
