# AI Carry 2.0.2 → 2.0.3

2.0.3 不要求用户学习一套新升级流程。仍然从看板或当前对话说“检查并升级 AI Carry”，先看只读预览，再单独确认这一次升级。

## 这次升级解决什么

2.0.2 已经把可修复的小故障限制在当前项。2.0.3 进一步把实例平时的持久变化和母版升级连到同一份轻量兼容协定：实例安装软件、Skill、组件，保存记忆、能力、SOP，或接收新母版时，都要清楚内容由谁拥有、升级时如何保留、失败时如何恢复，以及用户需要知道什么。

协定不规定固定字段、目录数量、时间戳或一套死迁移步骤。当前实例的 Agent 应读取真实 manifest、现有所有者和受影响内容，自主选择：

- 原样保留；
- 适配新接口或表达；
- 重新连接本机工具；
- 从正式真源重建索引或看板；
- 暂时停用一个不兼容的可选项，同时保留原件。

只有可能覆盖用户数据、混淆所有权、泄露私密内容，或必需能力经过合理修复仍不可用时，才暂停正式切换并说明最小决定。一个可选组件、索引、Skill 或本机工具的问题不能拖停整个 AI Carry。

## 升级时保留什么

2.0.2 实例的身份、方向、`created_from`、档案、记忆、能力、SOP、经验、候选、验证记录、Skill、组件、专业工作区、本机绑定、私密内容、问题报告、任务交接、未来字段和未知文件默认原样保留。升级不会为了证明“符合协定”给每个资产新增字段，也不会建立第二套中央登记。

母版拥有的产品文件按 2.0.3 发布清单更新；`instance/manifest.toml` 只迁移产品版本和确实必要的兼容引用，启动胶囊和双份快照从合并后的真实实例重建。看板刷新失败只留下待刷新项，不撤销已经安全安装的核心。

公开 1.4.8、保留的本地 1.4.9、2.0.0、2.0.1 和 2.0.2 都是 2.0.3 的直接来源，不需要先逐版升级。

## 完成标准

- 2.0.3 核心、实例身份和用户内容可以读回；
- 本次真正受影响的能力完成适配、重连、重建或明确的局部停用；
- 本机与私密内容没有进入公开母版或错误的便携范围；
- 回退仍可用，第二次执行不再产生变化；
- Agent 用自然语言说明实际变化、自动处理、保留内容、局部限制和推荐下一步。

固定 `v2.0.3` 标签、正式 Release、公开 `main`、发布清单和完整目标树全部一致，并且用户明确确认这一次升级后，2.0.3 才能替换实例。本地候选或包内自述不能自行取得这项权力。
