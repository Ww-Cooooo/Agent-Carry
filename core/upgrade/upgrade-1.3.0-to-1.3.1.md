# 1.3.0 → 1.3.1 升级说明

这是一个发布 authority、空结构占位语义和主动学习引导一致性补丁。它不重新迁移 1.3.0 已经完成的 Asset Schema 1.3 授权与成熟度闭包，也不改变实例方向、身份、档案、学习政策、资产正文、验证记录、专业扩展或本地私密层。

## 为什么仍要用隔离副本

只有官方固定 `v1.3.1` 标签、对应 Release 对象、`release-manifest-1.3.1.toml` 和解压后的完整文件树一致，且用户明确同意本次升级时，才可把它作为目标。清单中“已发布”只证明这个固定发布可用于实例替换，不授权任何新的提交、推送、标签、Release 或 Pages 动作。

先复制 1.3.0 实例到新建隔离副本并冻结完整路径、字节、链接／重解析点、大小写碰撞和平台元数据。真实实例保持原样，直到隔离结果、稳定入口和回退都通过并再次由用户决定是否切换。

## 实际变化

1. 用固定 1.3.1 发布树替换模板拥有的产品文件；用户拥有的实例资产、工作区、信号、治理状态、验证记录和 `.assistant-*` 本地内容全部保留。
2. 把实例清单的产品版本更新为 1.3.1，不改变实例 ID、方向锁、档案引用、交流方式或学习政策。
3. 根据更新后的精确实例清单重建严格启动胶囊，并核对来源摘要、身份、版本、方向和极小启动预算。
4. 从合并后的实例真源重建 public／dist 两份看板快照，要求逐字节一致。
5. 不重新迁移 1.2.1 的旧授权、确认门或成熟度；1.3.0 中已有的 `review`／`needs-evidence` 状态原样保留，不能借补丁制造批准或验证记录。

## 九个占位文件不是私密内容

目标发布仍禁止整个 `.assistant-local` 与 `.assistant-private`。发布清单只允许九个逐字列出的普通零字节 `.gitkeep` 越过宽泛禁止，用来保留公开空目录结构。任一文件含正文、不是普通文件、路径不同、是链接／联接／重解析点，或出现第十个 `.assistant-*` 文件，都停止；ZIP 目录记录只是容器元数据，不计为可复制正文。

## 验收与回退

- 来源 1.3.0 完整树中除明确的模板替换、实例清单、启动胶囊和派生快照外，所有路径逐字节保留；
- 启动入口返回 1.3.1、原实例身份和原方向，且不加载资产正文或私密层；
- 两份看板快照相同并来自合并后的实例真源；
- 同一迁移第二次执行零变化；
- 任一步失败恢复隔离副本的完整旧树，并保留失败现场；
- 用户确认切换前，真实 1.3.0 实例不被覆盖、合并、删除或重命名。

用户不需要打开终端或理解发布清单。宿主 Agent 应用普通语言报告目标发布是否可信、会更新什么、会保留什么、回退在哪里，以及是否仍在隔离副本；不能因为网页显示“Release”就跳过固定标签、完整树和 authority 核对。
