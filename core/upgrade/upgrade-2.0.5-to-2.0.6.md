# AI Carry 2.0.5 → 2.0.6

2.0.6 沿用原来的轻量升级入口。请从看板或当前对话说“检查并升级 AI Carry”，先看只读预览，再单独确认本次升级；不要手工复制产品文件。

## 这次修复什么

- 旧实例内置记忆治理卡中仍代表当前产品的两个已知旧名短语会改为 AI Carry；排期、用户历史和其他正文保持不变。无法唯一识别时原样保留，不做全库替换。
- 私密迁移的 Python 扫描器与正式共享秘密边界一致，补齐 DSA 私钥、GitHub PAT、OpenAI 项目令牌和 AWS 临时访问键等类别。
- Skill 的导出 ZIP 或文件夹丢失时，只把这一项标为载体已失效；可编辑源、其他 Skill、对话和 AI Carry 主体继续可用，可按引导重新生成载体。
- 看板当前以 1024px 及以上电脑窗口为正式支持范围；手机窄屏不进入升级验收，也不能因此把升级或其他能力判为失败。
- 第三方许可证再生成是维护者发布检查，需要隔离开发副本中的锁定依赖；普通安装和实例升级不需要 `node_modules`。

## 升级时保留什么

1.4.8、保留的本地 1.4.9、2.0.0、2.0.1、2.0.2、2.0.3、2.0.4 和 2.0.5 都可直接升级。实例身份、方向、`created_from`、档案、记忆、能力、SOP、经验、候选、验证记录、Skill、组件、专业工作区、本机绑定、私密内容、问题报告、任务交接、未来字段和未知文件继续保留。

本次只替换母版拥有的产品文件、更新实例产品版本，并在确实命中稳定内置治理卡时执行上述有界短语迁移。随后从合并后的真实实例重建启动胶囊与双份快照。单个 Skill 载体、快照或其他可修复派生项失败只留下定向重试；身份、用户数据、私密或所有权不可信时只暂停相关写入或正式切换。

## 完成标准

- 新版核心、实例身份和用户内容能够读回；
- 旧治理卡不再向当前看板投影错误产品自述，排期和用户历史逐字保持；
- 丢失 Skill 载体只限制对应 Skill，可编辑源与其他能力仍可使用；
- Python 与正式共享秘密边界一致；
- 启动胶囊和双快照闭合，第二次执行没有变化。

只有固定 `v2.0.6` 标签、正式 Release、公开 `main`、发布清单和完整目标树一致，并且用户明确确认本次升级后，2.0.6 才能替换实例。本地候选或包内自述不能自行取得这项权力。
