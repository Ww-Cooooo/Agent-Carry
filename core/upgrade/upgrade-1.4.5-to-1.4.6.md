# 从 1.4.5 升级到 1.4.6

本补丁让 Skill 工坊从“生成本地草稿后再想办法分享”闭合为真实可交付流程：生成前选择 ZIP、独立文件夹、链接或本机保留；Agent 自动处理所选方法的隔离副本、检查并生成载体。它不把升级本身变成一次 Skill 操作。

## 升级前

1. 只接受固定 `v1.4.6` 标签、对应正式 Release、`release-manifest-1.4.6.toml` 和解压树互相一致的来源。
2. 在尚不存在的隔离目录中处理，冻结完整 1.4.5 源树、实例 ID、manifest 摘要和回退点；不得在真实实例上直接覆盖、合并或重跑首次实例化。
3. 区分空模板与已实例化助手。空模板必须没有 `instance/skills/exports/index.toml`、可编辑 Skill、分享载体或安装条目。

## 已有实例怎样保留

- `instance/skills/**` 整体属于实例：requirements、已安装路线、本地导出索引、可编辑 Skill 文件夹、已有生成包、分享载体、链接字段和未知字段都逐路径、逐字节一致。
- 旧 `draft`、`ready`、`review` 条目无需先迁移。`draft` 继续显示待完善，`review` 继续显示需要复核；缺少新交付字段的旧 `ready` 只在新版看板投影为“分享方式待选择”。
- 升级不会为旧条目猜 ZIP、文件夹或链接，不会在升级过程中生成 ZIP、复制文件夹、检查外来包、联网、安装或分享，也不会刷新导出时间。
- 只有用户以后真正打开这一项或提出分享时，Agent 才问一次交付方式，再从仍然存在的可编辑真源生成一个不覆盖旧文件的载体。
- 单个 Skill 的交付信息异常只影响这一项：载体缺失或内容摘要漂移显示需要更新，已知字段不闭合显示需要复核；其他 Skill、看板、对话和 Agent Carry 主体继续可用。

## 隔离合并顺序

1. 从固定 1.4.6 目标树取得模板所有文件。
2. 对空模板保持完整空态；对实例只把 `instance/manifest.toml` 的产品版本从 1.4.5 更新为 1.4.6，并按发布清单合并所有实例所有内容。
3. 从合并后严格 manifest 重新生成 `instance/startup-capsule.toml`。
4. 从合并后正式真源重新生成 `dashboard/public/snapshot.js` 与 `dashboard/dist/snapshot.js`；两份必须逐字节一致。旧导出索引仍保持原字节，只允许快照增加低敏交付方式与计算状态，不得投影来源 ID、入口、本机路径、摘要或链接。
5. 逐路径、逐字节核对所有 preserve 路径，确认没有新增、删除、改名或时间漂移。相同输入第二次执行必须零变化。
6. 文件切换通过后，在当前原子动作的安全节点沿用 1.4.5 的当前对话接续规则：重新核对产品版本、同一实例 ID 和 manifest 摘要，只加载本次相关最小规则并自动验证一项无破坏行为。新任务仍只是不可变宿主阻止原地接续时的最后兼容路线。

## 代表性验收

- 空 1.4.5 模板升级后等于正式 1.4.6 空模板，两个标准首次创建场景仍通过。
- 合成实例至少包含一个旧 `draft`、一个旧 `review`、一个没有任何交付字段的旧 `ready`、一个已有载体的 Skill，以及普通资产、验证、候选、组件、扩展、工作区、本机绑定、私密哨兵和未知字段。
- 除产品版本、启动胶囊和由合并真源生成的两份快照外，所有实例所有字节保持不变；旧 `ready` 的索引仍无交付字段，但看板显示“分享方式待选择”。
- 从可编辑真源真实生成 ZIP 和独立文件夹并重新隔离检查，逐文件字节一致；路径穿越或损坏 ZIP 在创建目标目录前被拒绝。
- 修改可编辑真源或移走载体后，只把这一项投影为需要更新，不回写、不删除、不阻塞整份快照。
- 在 manifest、胶囊、快照等代表故障点注入失败时，完整源实例不变；第二次执行没有记录、载体或时间变化。

任何身份、来源、发布 authority、私密边界、保留字节或完整树核对失败都保留隔离现场并停止替换。不要通过放宽检查、重写旧索引、删除冲突载体、猜测分享方式或修改真实实例来获得通过。
