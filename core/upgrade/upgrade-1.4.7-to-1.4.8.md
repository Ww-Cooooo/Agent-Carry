# 从 1.4.7 升级到 1.4.8

本补丁把三条已有规则补成随包可执行的本地入口：首次创建、普通学习保存、共享 Skill 接入。它减少模型手写正式文件和事务字段造成的脆弱性，不增加后台服务、中心数据库、市场或企业式回归流程。

## 升级前

1. 只接受固定 `v1.4.8` 标签、对应正式 Release、`release-manifest-1.4.8.toml` 和解压树互相一致的来源。
2. 在尚不存在的隔离目录中处理，冻结完整 1.4.7 源树、实例 ID、manifest 摘要和回退点；不得在真实实例上直接覆盖、合并或重跑首次实例化。
3. 区分空模板与已实例化助手。空模板升级后仍不能包含真实档案、使用回执、学习记录、Skill、用户文件或正式资产。

## 已有实例怎样保留

- 实例身份、方向、档案、学习政策、记忆、能力、SOP、经验、候选、验证记录、组件、扩展、工作区、本机绑定、私密内容、Skill、导出状态、分享载体、任务交接和未知字段逐路径、逐字节保留。
- 升级不执行首次创建，不补造学习，不检查或安装 Skill，不运行包内脚本，不安装依赖，也不把旧导出状态机械改成新字段。
- 只把实例 manifest 的产品版本从 1.4.7 更新为 1.4.8，再从合并后的严格真源重建启动胶囊与两份一致快照。`created_from` 和其他实例历史保持不变。
- 新入口只在以后真正发生对应动作时按需加载。入口、Node 运行时或一项本地派生刷新不可用时，Agent 会说明局部降级并只暂停当前创建、学习或 Skill 动作；对话、已有结果和无关能力继续可用。

## 三条确定性入口

- **首次创建**：Agent 收集并展示用户确认过的语义设计，执行器统一生成全部身份文件、启动胶囊和双快照，在隔离候选中严格回读后一次切换；中途失败恢复完整空模板。
- **学习保存**：Agent 只提供人能读懂的学习内容；产品生成绑定内容摘要的预览和确认命令，用户一次真实选择后才原子写入、更新路线与快照并回读。模型不手写底层事务字段。
- **共享 Skill 接入**：文件夹、ZIP 或从链接取得的准确本地包先进入有界只读检查；预览绑定来源、摘要和安装目标，用户一次回复后才原子复制到本机 Skill 目录、逐字节回读并登记。检查和安装都不执行包内脚本或依赖。
- 只有当前任务工作区或正式登记索引的有界回读才能证明某个结果、Skill 或记录存在或不存在；没有核对时必须说“本次未核对”，不能把未知冒充为没有。

## 隔离合并顺序

1. 从固定 1.4.8 目标树取得模板拥有的全部产品文件。
2. 对空模板保持完整空态；对实例只更新产品版本，并按发布清单合并所有实例所有内容。
3. 从合并后的严格 manifest 重新生成 `instance/startup-capsule.toml`。
4. 从合并后的正式真源重新生成 `dashboard/public/snapshot.js` 与 `dashboard/dist/snapshot.js`，要求逐字节一致。
5. 逐路径、逐字节核对所有 preserve 路径；相同输入第二次执行必须零变化，不能刷新记录、确认、安装或时间。
6. 文件切换通过后，在当前原子动作的安全节点接续最小 1.4.8 规则，并自动做一项不修改用户资产的代表行为核对；不把测试交给用户。

## 代表性验收

- 空 1.4.7 模板升级后等于正式 1.4.8 空模板，并继续通过通用和剪辑两场景首次创建生命线。
- 合成实例包含普通资产、验证、候选、组件、扩展、Skill 导出与载体、已安装本机 Skill、任务交接、本机状态、私密哨兵与未知字段；除产品版本、启动胶囊和双快照外全部字节不变。
- 首次创建完整闭合且故障恢复空模板；学习预览到确认写入可回读且幂等；共享 Skill 一次确认后安装登记，脚本保持未执行，同名冲突和危险包只隔离自身。
- 未读取的状态保持“本次未核对”；派生看板刷新失败不撤销已经完整回读的有效 Skill 安装，只报告看板待刷新。
- 在 manifest 后注入代表性故障时，完整 1.4.7 源实例不变；第二次执行没有记录、时间、安装或文件变化。

任何身份、来源、发布 authority、私密边界、保留字节或完整树核对失败都保留隔离现场并停止切换。不要通过放宽校验、改写用户资产、伪造学习、执行外来代码、删除冲突文件或重跑首次创建获得通过。
