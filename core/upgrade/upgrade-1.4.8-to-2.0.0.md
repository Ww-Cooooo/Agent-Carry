# 从 Agent Carry 1.4.8／1.4.9 升级到 AI Carry 2.0.0

AI Carry 是 Agent Carry 的新名称。2.0.0 同时保留本地 1.4.9 已完成的“同一 Skill 新版接入”和“问题报告”能力；正式 1.4.8 和本地 1.4.9 是直接升级来源，公开用户不需要先经过未公开的 1.4.9。

这次升级改变产品名称和新生成的机器身份，不改变用户已经建立的助手身份。它不是全文替换，也不会把历史里的 Agent Carry、旧 `created_from`、用户资产正文或别人制作的 Skill 擅自改成新名称。

## 正式发布边界

1. `release-manifest-2.0.0.toml` 只为固定 2.0.0 建立条件式升级 authority。没有固定 `v2.0.0`、对应正式 Release、匹配的解压树和用户对该次升级的选择时，不得替换真实实例；包内版本文字或 `status=published-release` 不能跳过现场核验。
2. GitHub 仓库仍位于 `Ww-Cooooo/Agent-Carry`。产品改名不等于仓库已经改名；远程仓库改名必须是以后单独授权的外部动作。
3. 所有预演只在尚不存在的隔离目录中进行。不得在 Git 开发工作树、依赖目录或真实实例上试着全文替换。

## 用户看到的流程

1. 用户在原有看板复制“检查官方更新”请求，或直接说“检查我的 AI Carry／Agent Carry 有没有官方新版本”。
2. Agent 核对登记的官方来源、固定发布、目标清单和解压树。取得目标树只用于检查，不等于安装或替换实例。
3. 用户明确要求检查更新后，Agent 运行只读入口 `dashboard/scripts/ai-carry-upgrade-cli.mjs prepare --source <当前实例根> --target <目标根>`。CLI 自己通过 GitHub HTTPS API 核对非草稿、非预发布的正式 Release，把固定 `v2.0.0` 标签解析到准确提交，再按 Git blob 逐文件核对目标整树与发布清单；调用者手写的 JSON、模拟标记、目标包自己的版本文字或 `[release_boundary]` 都不能冒充官方来源。CLI 同时按清单分类目标路径，禁止未列出、私密、本机或开发文件进入写集。Agent 只把返回的 `userPreview` 原样展示，不自己推断替换／迁移／保留清单。
4. 用户看完预览后，在下一条独立消息明确回复“升级”或“确认升级”。承载对话的 Agent 才执行这次 `prepare` 返回的同次 `confirmCommand`，用户不需要操作终端。CLI 重新核对正式 Release、目标字节、实例状态、确认引用和精确确认字符串，但不会把普通命令行参数伪装成聊天角色认证；宿主负责保证调用确实发生在本次用户确认之后。“迁移升级”、长句中的“升级”或预览前的泛泛意愿都不是最终确认，模型也不手写 manifest、不逐文件替换品牌。
5. 工具在隔离候选中完成合并、启动胶囊和双快照重建、逐字节保留核对；然后保持用户当前打开的实例根路径不变，只事务替换发布清单明确拥有且实际变化的产品文件。每个变化文件的旧前像和恢复清单留在同父级回滚包；工作区、本机层、私密层和未知根文件原地不碰，不为升级复制整棵用户目录。
6. 文件切换后，目标入口可以回读磁盘闭包与一项代表路线是否存在，但不能仅凭静态字符串声称当前宿主会话已经采用新版或真实行为已经通过。宿主能给出真实重载／行为事实时再闭合后两项；否则如实显示待接续，并说明下一次自然打开会读取新版。用户不需要另开专门的测试任务。

## 哪些会变

- 当前产品名称、当前 README／安装说明、看板标题和新生成的产品输出使用 `AI Carry`。
- 产品 ID、核心 ID、启动胶囊 ID、组件登记的新记录类型、组件新接口和新快照全局变量使用 `ai-carry`／`AI_CARRY` 规范。
- 已实例化 manifest 只把产品版本从 1.4.8 或 1.4.9 更新到 2.0.0；随后从合并后的正式真源重建 `instance/startup-capsule.toml` 和两份一致快照。
- 2.0.0 继续提供旧组件接口和旧快照变量的有界兼容读取；新写入不再产生旧产品身份。

## 哪些必须原样保留

- `instance_id`、`created_from`、方向、档案、交流方式、学习政策、地图、信号、治理卡和宿主档案。
- 记忆、能力、SOP、经验、候选、验证记录、组件正文、扩展、工作区、本机软件绑定和私密内容。
- Skill requirements、已安装 Skill、可编辑真源、导出索引、生成包、分享载体，以及处于“已生成但尚未选择分享方式”的旧条目。
- 问题报告、任务交接、未来字段和未认识的用户文件。

候选构建实际读取的 `instance/` 正式文件按路径和字节核对；工作区、本机层、私密层和未知根文件不进入写集，因此保持原地而无需复制或读取正文。升级不会检查、安装、升级或执行 Skill，不执行组件或工作区脚本，也不会上传、分享、建 Issue、提交或发布任何内容。

## 旧接口怎样继续工作

- 旧 `agent-carry-instance-component-registry`、`agent-carry-instance-component` 和 `agent-carry.instance-component@1` 仍是合法兼容输入；升级只读取并保留，不机械改写组件文件。
- 新组件使用 `ai-carry-instance-component-registry`、`ai-carry-instance-component` 和 `ai-carry.instance-component@1`。
- 新快照使用 `AI_CARRY_SNAPSHOT` 等变量，同时提供一代只读 `AGENT_CARRY_*` 别名，避免旧缓存页面在文件刚升级时变成空白；旧 1.4.x 快照也仍可读取。
- 新隐私迁移包使用 `ai-carry-private-migration`，旧 `agent-carry-private-migration` 包保持可读。兼容读取不等于重新导出或发送旧包。

## 原子升级和故障范围

`prepare` 只读绑定现场核验的正式 Release、固定标签提交、目标 Git 树、目标发布边界、实例身份、清单分类写集和候选构建所需的实例正式文件，并返回六类预览和确认引用。它不接受调用者自写的来源权威，不遍历工作区正文、本机层、私密层或未知根文件，也不会创建候选或改动实例。切换前还会检查根与触碰路径的重解析点、大小写／Unicode 冲突；Windows 上发现硬链接、命名数据流、受保护或显式 DACL、所有者漂移、只读／系统／加密属性，或无法可靠完成硬链接／数据流枚举时，只暂停这次升级，不拆链接拓扑、不改权限、不猜测丢弃。`confirm` 必须使用同一目标、同一引用和用户在绑定预览后的独立确认；任何漂移都重新预览。这里约束的是正常 Agent 行为和升级事务，不虚构一个能够抵御恶意本地写入者的权限沙箱。

候选验证通过前不修改正式根。`confirm` 重新完成现场核验后，会把目标复制到隔离候选并再次核对整树指纹；预览后或复制中的目标漂移都不会进入安装。Windows 上当前 Agent 往往正把实例根作为工作目录，因此升级不得依赖重命名整个根目录。工具只为实际变化的清单拥有路径记录前像并逐项暂存、替换和回读；暂存名包含本次编号，暂存记录先进入恢复状态再复制，所以普通校验异常会清理本次临时文件，进程被强制中断留下的旧临时文件也不会卡住下一编号重试。本次新建的目录也进入回滚清单，失败时只删除仍为空的事务目录，不碰后来出现的内容。未知源路径没有删除授权，永远不会因为目标包中不存在就进入 removal。第一处正式文件变化后注入失败时，已变化路径按事务记录逆序恢复并逐路径核对。极端情况下无法自动恢复时，源、候选和回滚现场全部保留，并只暂停本次升级。旧失败现场使用带编号的新尝试继续，不删除旧现场，也不会让相同源和目标永久无法重试。一个旧可选组件、待复核工作区、旧 Skill 条目或派生快照异常只暂停对应组件或本次升级；对话、已有结果和无关能力继续可用。

第二次对已升级根执行相同入口时，仍先现场核对正式 Release、固定标签目标整树和目标发布边界，再核对本地核心、启动胶囊、产品身份、两份一致快照，以及本地静态产品文件与官方目标的逐路径字节；全部一致才返回“已是当前版本”。混合、本地候选或损坏的 2.0.0 根不能借版本号提前通过。健康根不刷新时间、不新增记录、不重写快照或用户文件；回执如实注明这次只读检查使用了网络。

## 升级后回执

完成报告分别说明：GitHub 正式 Release／固定标签提交／Git 树与目标字节是否现场闭合、目标包发布边界是否允许实例替换、用户交互确认是否发生、文件是否安装、实例是否切换、当前会话是否采用 2.0.0、代表行为是否实际通过、变化文件回滚包在哪里，以及候选读取的实例正式文件是否零漂移。只有目标产品文件或严格启动真源无效才回滚文件事务；当前会话暂时不能由宿主证明重载时，已升级实例和无关能力继续可用，并明确说明新版行为将在下一次自然启动生效。通用 JSON 判定器和静态文件工具都不得把后两项写成已通过。

本地 1.4.9 的详细历史能力仍可查阅 `upgrade-1.4.8-to-1.4.9.md` 和 `release-manifest-1.4.9.toml`；它们是未公开候选记录，不会被改写成已发布事实。
