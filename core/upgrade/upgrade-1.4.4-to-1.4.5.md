# 1.4.4 → 1.4.5 长期对话升级连续性补丁说明

1.4.5 是正式发布的升级连续性补丁。升级仍必须先在尚不存在的隔离目录中组装和验证；只有官方固定 `v1.4.5` 标签、对应 Release、`release-manifest-1.4.5.toml` 和源码 ZIP 解压树一致，并且用户明确选择升级这个固定版本时，才可替换实例。该固定版本不授权未来的提交、推送、标签、Release 或 Pages。

## 这次修复什么

- 长期使用同一个对话时，每个新的实质用户目标开始前只比较一次极小 Agent Carry 启动基线：产品版本、实例 ID 与 manifest 摘要。宿主或 Codex 版本不是 Agent Carry 版本；同一目标的连续回复不重复检查，基线完全一致也不加载升级正文。
- 文件在当前对话中切换后，Agent 默认在当前原子操作结束后的安全节点继续：重新运行严格启动入口，只加载目标版本的最小入口和本次相关规则，检查不可变宿主规则冲突，再自动完成一项真实、无破坏的代表行为验收。
- 普通重读新版文件、版本号、哈希、胶囊、快照或静态字符串仍不能冒充采用新版。只有有界接续步骤全部闭合，当前对话才报告已经采用新版产品规则；这不声称宿主内部系统提示词已被改写。
- 宿主确实阻止原地接续时，只保留受影响行为为待接续；有效实例、用户数据、普通对话、只读能力和无关能力继续可用。新任务只在用户希望立即使用受影响行为时作为最后兼容路线，不是默认验收任务。
- 验收由 Agent 自动完成并自然语言报告。用户无需输入测试提示词、检查文件、判断内部状态或为了证明升级成功专门新开任务。

## 空模板分支

- 从完整 1.4.4 空模板在尚不存在的隔离目录组装 1.4.5 目标；
- 模板继续保持 `instance_id=template`、未选择方向、未批准档案，以及 0 项记忆、能力、SOP、经验、候选、验证记录、组件、待办和 Skill；
- 不生成会话记录、行为结果、导出索引、Skill 包或演示资产；
- `instance/manifest.toml` 的 `created_from` 与产品版本使用 1.4.5，严格启动胶囊和两份快照从同一清单重新生成；
- 第二次执行相同文件事务不得改变文件、记录、时间或快照字节。

## 已实例化助手分支

- 冻结完整 1.4.4 来源树、回滚点，以及切换前当前对话的 Agent Carry 产品版本、实例 ID 与 manifest 摘要；
- 原样保留实例身份、`created_from`、方向、档案、交流方式、学习政策、地图、信号、治理排期、宿主、Skill 需求与已安装路由、本地导出索引与生成包、记忆、能力、SOP、经验、验证记录、候选、组件、扩展、工作区、本机绑定、私密引用、用户正文和未知字段；
- 只把实例清单中的产品版本从 1.4.4 更新为 1.4.5，不重新实例化，不刷新未变化时间，不制造资产、证据、候选、待办、组件、Skill、会话或行为证明；
- 从合并后的严格实例清单重建启动胶囊，再从合并后的正式真源重建 public/dist 双快照并要求逐字节一致；
- 所有保留路径逐路径、逐字节一致且第二次文件执行零变化后，才可切换。

## 当前对话采用与故障范围

- 文件事务完成后，等当前原子操作到达安全节点，再运行严格启动入口；核对目标版本、同一实例 ID 和 manifest 摘要，仅接续最小新版规则；
- 代表行为必须来自本次发布说明，并且真实、无破坏。若它需要写用户数据、发送外部内容或新授权，只验证到实际后果发生前的路线和门禁；不能借升级验收扩大授权；
- 有界接续完成后，分别报告来源、文件、实例保留、当前对话采用和自动行为结果。用户不需要亲自再测一次；
- 宿主不可变规则阻止接续或单项行为失败时，不回滚有效新实例，不停止整个 Agent。只隔离该行为或升级完成结论，保留证据并由 Agent 定向修复；
- 只有目标文件、实例切换、严格启动胶囊或正式快照无效时，才恢复完整 1.4.4 文件事务前像。

每次自动重试、局部隔离、待接续或回滚都必须用自然语言说明发生了什么、影响范围、数据状态、仍可用内容和推荐下一步。
