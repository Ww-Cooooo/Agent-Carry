# 从 Agent Carry 1.4.8／本地 1.4.9／AI Carry 2.0.0 或 2.0.1 升级到 AI Carry 2.0.2

## 这次修什么

2.0.2 把“必须共同成功的核心事实”和“可以重建的辅助状态”分开。首次创建先完成实例身份、正式档案和方向；启动胶囊、看板、空索引或登记表随后独立刷新。学习、Skill 安装和升级也以正式结果为准：索引、提醒、快照或看板刷新失败时留下清楚的待修项，不撤销已经安全成立的内容，也不停止普通对话和无关能力。

真正的硬边界没有放松：manifest 身份不可信、用户数据所有权不清、私密内容可能越界，或实际写入路径无法安全判断时，仍停止对应持久操作并保留现场。

2.0.2 还补上复制实例的本机运行时边界。副本里的 `.assistant-local/**` 绑定可能仍保存正式实例路径，第三方工具也可能在共享安装目录附近写缓存。需要启动组件或专业扩展的本机工具时，随包入口只读检查本次明确使用的少量 JSON／TOML 绑定：回指正式实例、共享运行时未核验、路径跨越链接或无法解析时，只把当前能力记为 `limited`。预检不扫描整台电脑、不执行工具、不安装依赖、不改写绑定，也不在结果中暴露真实绝对路径。

## 谁可以直接升级

- 已公开的 Agent Carry 1.4.8；
- 曾保留在本地、从未公开的 Agent Carry 1.4.9；
- AI Carry 2.0.0；
- AI Carry 2.0.1。

因此，尚未成功跨过 2.0.0 或 2.0.1 的旧实例可以直接选择正式 2.0.2，不需要先串行安装中间版本。

## 用户怎么操作

仍从现有 AI Carry 看板的升级入口开始。Agent 使用目标包自带的确定性升级入口先做只读 `prepare`，向用户展示同次绑定的自然语言预览；只有用户在下一条独立消息明确回复“升级”或“确认升级”后，才运行返回的 `confirmCommand`。用户不需要操作终端。

`prepare` 在用户明确检查更新时现场核对 Latest Release、固定 `v2.0.2` 轻量标签、公开 `main`、Git 树、目标逐文件字节和发布清单。`confirm` 不重复联网，只复核同次预览绑定的本地来源、目标、实例和写入集合。真实漂移会让旧确认失效；普通 DNS、HTTP 或网络波动不会否定已经核验且未变化的候选。

## 升级会保留什么

升级保持用户当前打开的实例根目录不变，并逐路径、逐字节保留实例身份、`created_from`、方向、档案、记忆、能力、SOP、经验、候选、验证记录、组件、专业工作区、本机工具绑定、私密引用、Skill、导出载体、问题报告、任务交接、未来字段和未知文件。

本次升级不会运行本机工具、Skill、组件或工作区脚本，不会处置缓存，不会扫描实例工作区正文，也不会安装依赖。它只更新目标母版拥有且实际变化的产品文件、实例 manifest 中的产品版本和严格启动胶囊；两份一致快照在核心切换后刷新，刷新失败只留下“看板待刷新”。

## 事务、代表行为与恢复

1. `prepare` 现场核对官方来源一次，并只读计算实例兼容性和预计写入集合。
2. 用户确认后复核同一预览绑定的本地事实，把目标复制到隔离候选，并重新核对目标字节。
3. 在候选中叠加必要的实例真源，生成严格 manifest 和启动胶囊；不执行任何实例工具。
4. 仅事务替换发布清单拥有且字节变化的核心产品文件；旧字节进入带清单的回滚包，失败时逆序恢复。
5. 核心切换成功后刷新双快照；快照失败时保留有效核心和旧快照，返回明确重试入口，不把整个升级回滚。
6. 后续代表行为如果需要在实例副本中启动本机工具，Agent 先运行 `dashboard/scripts/copied-instance-runtime-boundary.mjs`。不通过时只把这项行为标为 `limited`，不停止无关能力。

第二次对已经安装且未漂移的 2.0.2 执行检查时，会先核对官方来源、本地静态产品字节、启动胶囊和快照，再返回零变化；不会刷新用户内容、绑定、缓存、资产、时间或报告。

## 正式发布边界

只有官方 Latest Release、`v2.0.2` 正式 Release、固定轻量标签、公开 `main`、发布清单和解压后的完整目标树一致，并且用户明确选择这一次实例升级时，2.0.2 才能替换实例。

这份发布清单只为固定 2.0.2 建立条件式升级权威，不授权未来提交、推送、标签、Release、Pages、仓库改名、真实实例数据处置或其他远程动作。
