# AI Carry 2.0.3 → 2.0.4

2.0.4 不增加新的升级流程。仍然从看板或当前对话说“检查并升级 AI Carry”，先看只读预览，再单独确认这一次升级。

## 这次修复什么

- 启动预算检查不再从 Schema 示例或中文说明里抓数字。`assistant.toml` 是唯一机器真源，检查仍会核对真实启动大小、信号投影预算和严格启动胶囊。
- 实例升级后只运行这次事务返回的 `sessionReentryCommand`，然后继续原工作或完成一项相关的无破坏代表行为。开发仓库的 `check:*`、构建依赖和许可证生成工具不属于实例升级门禁。
- 母版发布仍会检查启动预算、锁定依赖的许可证、公开边界和关键用户旅程；这些维护者检查不会被塞进普通实例。

## 升级时保留什么

1.4.8、保留的本地 1.4.9、2.0.0、2.0.1、2.0.2 和 2.0.3 都可直接升级。实例身份、方向、`created_from`、档案、记忆、能力、SOP、经验、候选、验证记录、Skill、组件、专业工作区、本机绑定、私密内容、问题报告、任务交接、未来字段和未知文件继续原样保留。

本次只更新母版拥有的产品文件和实例产品版本，再从合并后的真实实例重建启动胶囊与双份快照。可重建投影失败只留下定向重试，不撤销已经安全安装的核心；身份、用户数据、私密或所有权不可信时仍只暂停受影响的写入或正式切换。

## 完成标准

- 2.0.4 核心、实例身份和用户内容可以读回；
- 启动预算检查通过，并能拒绝真实的信号预算漂移；
- `sessionReentryCommand` 与一项相关代表行为完成，不运行开发检查全集；
- 回退仍可用，第二次执行不再产生变化；
- Agent 用自然语言说明实际变化、保留内容、局部限制和推荐下一步。

固定 `v2.0.4` 标签、正式 Release、公开 `main`、发布清单和完整目标树全部一致，并且用户明确确认这一次升级后，2.0.4 才能替换实例。本地候选或包内自述不能自行取得这项权力。
