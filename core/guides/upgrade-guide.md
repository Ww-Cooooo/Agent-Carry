# 模板升级指南

仅在用户明确要求检查或应用模板更新时读取。实例运行良好时不强制升级。

## 用户看到的简单流程

1. 用户直接说“帮我检查 Agent Carry 有没有官方新版本”，或在看板中复制升级请求；不需要自己寻找版本清单。
2. Agent 读取 `core/upgrade/official-source.toml`。允许联网时，只从其中登记的官方公开仓库和正式 Release 检查；无法联网时，请用户提供已经下载到本地的升级包，不在搜索结果或镜像站中猜哪个是官方版本。
3. Agent 告诉用户当前版本、找到的目标版本和来源，只预览本次变化、个人内容保留方式与冲突，不立即升级。
4. 用户选择：保留现状，或迁移升级。
5. Agent 自动执行、验证并报告；用户不需要操作终端。

检查更新只在用户明确提出时进行。Agent Carry 不后台联网、不自动下载，也不会因为发现新版本就强制升级。公开仓库不需要 GitHub 登录；如果用户指定其他仓库、附件或镜像，Agent 必须明确说明它不是登记的官方来源，并在读取或下载前让用户决定。

## 预览

Agent 读取当前 `instance/manifest.toml`、`core/upgrade/official-source.toml`、目标发布清单和 `core/ownership.toml`，将文件分为：

- 模板核心：可按清单替换或迁移。
- 实例身份与个人资产：默认保留。
- 正在使用的扩展接口：检查兼容范围。
- 本地私密和派生文件：不从升级包覆盖。

如果用户改过模板核心，明确提示“该实例存在个性化核心修改，默认更新可能无法直接应用”。不要让用户面对复杂合并工具。

## 两个选择

- **保留现状**：跳过本次升级，实例继续工作。
- **迁移升级**：导出实例身份、偏好、记忆、能力、SOP、经验、延期卡、跨会话正式状态、长期治理卡的实例排期状态、不含秘密的宿主档案和批准过的进化成果；从新模板创建干净实例；按 Schema 迁入并重建路由地图、唤醒胶囊、非启动时间索引和看板快照。长期治理卡按稳定 ID 使用新模板的正文、频率与步骤，同时保留实例自己的启停、锚点、上次完成、下次到期、延后和触发修订；缺失、重复或 ID 变化时作为冲突预览，不能重置成模板空态。旧核心改动不自动带入，除非用户把它明确认定为个人资产或扩展。宿主档案保留的是历史观察，升级后在相关能力使用时重新验证。

升级前创建临时回滚副本。升级后检查入口、地图目标、资产风险／授权／成熟度字段、实例交流方式与学习政策、长期治理卡正文版本与实例排期字段、跨会话控制修订、触发注册表、唤醒胶囊与时间索引聚合、宿主接入协议／Schema、看板动作、快照、扩展接口和实例方向锁定。旧实例缺少 `profile.guidance_mode` 时按 `balanced` 兼容读取，只在用户调整交流方式或清单因其他正式变化被迁移时写入；不得借补字段改变锁定方向。Asset Schema 1.1 资产缺少新字段时按保守默认值读取，只在目标资产被使用、修改或复核时渐进补齐，不为升级全量展开正文。用户验收后自动删除临时回滚副本；用户自行生成的备份包不处理。

完整机器规则见 `core/upgrade/UPGRADE-CONTRACT.md` 和对应发布清单。升级包采用来源、清单与哈希做完整性检查，但不向普通用户承诺“官方绝对安全”。
