# 模板升级指南

仅在用户明确要求检查或应用模板更新时读取。实例运行良好时不强制升级。

## 用户看到的简单流程

1. 提供模板仓库中的版本说明/升级清单，或把离线升级包放入 Agent 指定的投递目录。
2. Agent 预览本次变化和冲突。
3. 用户选择：保留现状，或迁移升级。
4. Agent 自动执行、验证并报告；用户不需要操作终端。

## 预览

Agent 读取当前 `instance/manifest.toml`、目标发布清单和 `core/ownership.toml`，将文件分为：

- 模板核心：可按清单替换或迁移。
- 实例身份与个人资产：默认保留。
- 正在使用的扩展接口：检查兼容范围。
- 本地私密和派生文件：不从升级包覆盖。

如果用户改过模板核心，明确提示“该实例存在个性化核心修改，默认更新可能无法直接应用”。不要让用户面对复杂合并工具。

## 两个选择

- **保留现状**：跳过本次升级，实例继续工作。
- **迁移升级**：导出实例身份、偏好、记忆、能力、SOP、经验、延期卡、跨会话正式状态、长期治理卡的实例排期状态、不含秘密的宿主档案和批准过的进化成果；从新模板创建干净实例；按 Schema 迁入并重建路由地图、唤醒胶囊、非启动时间索引和看板快照。长期治理卡按稳定 ID 使用新模板的正文、频率与步骤，同时保留实例自己的启停、锚点、上次完成、下次到期、延后和触发修订；缺失、重复或 ID 变化时作为冲突预览，不能重置成模板空态。旧核心改动不自动带入，除非用户把它明确认定为个人资产或扩展。宿主档案保留的是历史观察，升级后在相关能力使用时重新验证。

升级前创建临时回滚副本。升级后检查入口、地图目标、资产风险／授权／成熟度字段、实例交流方式与学习政策、长期治理卡正文版本与实例排期字段、跨会话控制修订、触发注册表、唤醒胶囊与时间索引聚合、宿主接入协议／Schema、看板动作、快照、扩展接口和实例方向锁定。旧实例缺少 `profile.guidance_mode` 时按 `balanced` 兼容读取，只在用户调整交流方式或清单因其他正式变化被迁移时写入；不得借补字段改变锁定方向。Asset Schema 1.1 资产缺少新字段时按保守默认值读取，只在目标资产被使用、修改或复核时渐进补齐，不为升级全量展开正文。用户验收后自动删除临时回滚副本；用户自行生成的备份包不处理。

完整机器规则见 `core/upgrade/UPGRADE-CONTRACT.md` 和对应发布清单。升级包采用清单与哈希做完整性检查，但不向普通用户承诺“官方绝对安全”。
