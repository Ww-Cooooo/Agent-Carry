# Skill 初始化与小型路由

首次实例化只执行下面的“极小需求判断”；用户明确刷新 Skill，或真实任务命中一个尚未确认的 Skill 需求时，才展开相应条目。普通任务不扫描 Skill 仓库。

首次实例化时必须把 `instance/skills/requirements.toml` 的 `instance_id` 换成当前实例 ID，并写真实生成时间。判断只使用用户已经确认的初始任务和当前宿主最小档案：没有已确认的额外 Skill 需求时写 `status = "current"` 并保持空条目；信息不足时写 `status = "deferred"`。这不是宿主 Skill 全量盘点，也不授权安装任何东西。模板的 `status = "scan-after-instantiation"` 只是一条待完成标记，不得留在正式实例中。

1. 只有初始任务或当前真实任务确实需要额外 Skill 时，才从当前接入回执或本次实际观察读取少量相关 Skill 的名称、用途、入口和来源；宿主接入能力本身由 `HOST_INTEGRATION.md` 管理，不复制到 Skill 地图。
2. 根据实例方向和初始任务族，列出“必须、可选、不相关”三类；安装任何外部 Skill 前先加载外部安全边界，必要时做安全审查并取得用户确认。
3. 不因为模板作者使用过某个 Skill 就强制所有平台安装；优先使用当前 Agent 已具备的等价能力。
4. 在 `instance/skills/requirements.toml` 写小型路由：稳定 ID、可选标题、摘要、触发词、平台名称、实际入口、来源、状态、最后确认时间。旧条目没有标题时按稳定 ID 生成展示名，不为补展示字段阻塞调用。Skill 自身只是宿主已有能力时不重复登记组件；如果它同时新增实例文件、本机运行时、模型或跨组件接口，再按实例持续进化兼容协定登记对应独立组件和设备本地边界。
5. 普通任务只读这份小地图，命中后才读取具体 Skill；未命中不扫描完整目录。执行命中 Skill 时，如果它要求判断“已有成果”“没有先前产物”“已经安装”“不存在”或同源复用状态，只能依据当前任务已经明确的工作区、稳定来源身份或已登记小索引做有界回读。没有可用位置或索引时如实写“本次未核对”，不能把没查过说成“没有”；这一前置检查是可选时透明降级并继续，可证明为必需时也只暂停当前 Skill，不停止对话和其他能力。
6. Skill 被删除、替换或升级时，在同一正式变化中命中 `core/protocols/INSTANCE_EVOLUTION_COMPATIBILITY.md`，同步小地图、受影响能力／SOP 以及已有组件登记；兼容核对复用当前安装或修改授权，不额外询问一次。

这里采用“使用时校验”而不是启动轮询：只有实际调用某 Skill、宿主握手暴露相关 Skill 变化，或用户明确刷新时，才比较状态与最后确认时间。宿主的通用读取、写入、回传和保留能力记录在按需宿主档案中，Skill 地图只登记实际 Skill。未发现问题时不建立跨会话状态；发现缺失、替换、权限变化或语义不兼容且本次无法解决时，才向唤醒胶囊投影一条异常路线。

路由保存的是“本实例知道可以用什么”，不是把 Skill 正文复制进仓库。

用户主动要求把本实例的方法转换为 Skill，或安装别人分享的 Skill 时，改走 `core/guides/skill-workshop-guide.md`。安装共享文件夹或 ZIP 时使用 `dashboard/scripts/skill-install-cli.mjs` 的两步入口：`prepare` 负责有界检查和唯一预览，用户回复“安装”后按返回的 `confirmCommand` 原子复制、回读并登记；模型不手写 requirements 条目或安装事务。工坊不会在普通任务中自动分享，也不会把所有资产机械转换成 Skill；它完成转换或安装后再同步这里的小地图。
