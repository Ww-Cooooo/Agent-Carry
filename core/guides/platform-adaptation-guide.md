# 平台与换机适配

正式资产的语义不随 Agent、模型或操作系统变化。适配时只处理能力差异、路径、工具和展示层。

1. 若当前宿主只是新会话没有回执，先路由到 `host-session-resume`；若首次接入、宿主确已变化或状态无法确认，再路由到 `host-integration`。本指南只处理接入确认后的系统、路径、工具和展示适配。
2. 从已验证接入回执识别当前系统、宿主、可用工具、模型确认方式和文件权限，不把旧宿主档案当作当前事实。
3. 比较实例记录的本地路径；询问用户换机后对应目录是否变化。
4. 不要求不同电脑具有相同任务文件。只迁移用户选择的正式资产和隐私包，各设备可保存不同本地数据。
5. 对平台特有动作生成临时适配或说明；不要在核心中长期维护三套同义脚本。
6. 新平台无法直接支持某项能力时，保持能力语义不变，记录替代工具、限制和验证方式。
7. 检查新宿主能否读取跨会话控制记录和极小唤醒胶囊；只能接收文本时，改用启动胶囊和自然语言回执，不得声称已经直接持久化。
8. 完成后更新一个相关宿主档案和本地环境记录，不扫描全部宿主；若时区变化，比较带偏移量的正式提醒时间并重建时间索引与最早唤醒聚合，但不擅自改变原定时刻。最后更新看板快照，不修改实例方向。
9. 复制、升级或恢复完整实例时，路径规则同时防止绝对路径、`..`、链接／重解析跳转、大小写与 Unicode 规范化碰撞。深层路径使用短临时名和同目录原子替换；不能因为诊断目录名、时间戳或重复后缀过长制造新的平台失败。
10. Windows 上先判断普通继承权限是否足够；只有源对象存在必须保留的显式或受保护访问规则时才尝试复制对应 DACL。默认不复制 SACL 或所有者，不自动提权；工具退出码和错误输出必须一起核对。其他系统按等价的权限与扩展属性语义处理。
11. 看板入口应使用系统认可的可见位置和稳定根入口。采用或升级已有实例前先核对入口；内容切换后用入口回读、离线资源、快照身份、浏览器非错误状态和结果测试组合验收，精确地址栏读取只是可选增强。
12. 专业工作区只有在 `workspace/<extension-id>/extension.toml` 合法且任务命中时才展开。迁移和升级按清单区分便携、派生、当前设备和隐私引用路径；未登记内容原样保留并进入冲突预览，不由平台适配器猜测所有权。
13. 已登记实例组件按 `instance/components/registry.toml` 定向读取一个清单。便携接口语义保持不变，`.assistant-local/**` 设备绑定只在本机重新核验或重建，不把旧电脑绝对路径写进组件清单；普通平台适配不枚举全部组件或本机软件。

任何联网查平台资料前先加载外部安全边界。
